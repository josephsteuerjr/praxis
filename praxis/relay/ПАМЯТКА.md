# Реле: подписка ChatGPT как локальный API (Windows)

Реле — это маленькая программа, которая превращает твою **подписку ChatGPT**
(Plus/Pro) в обычный OpenAI-совместимый API у тебя на компьютере. Никакого
API-ключа OpenAI и API-биллинга не нужно: платишь только за подписку, а твой
агент (Hermes, OpenClaw, свой скрипт — что угодно, умеющее OpenAI API) ходит
на `http://127.0.0.1:5011`.

Честная оговорка: это неофициальный мост (реле говорит с бэкендом ChatGPT по
протоколу Codex). OpenAI такой способ не благословлял — используешь свою
подписку на свой страх. Наружу реле не торчит: слушает только твой компьютер.

## Изображения

С версии 0.8.4 реле также умеет генерацию и правку изображений через ту же
подписку: `POST /v1/images/generations` и `POST /v1/images/edits`, модель
`gpt-image-2`. Формат запросов и ответы — в [README.md](README.md#image-generation-and-edits).
Это отдельная модель изображений; ставить её основной текстовой моделью не нужно.

## Подготовка

- Windows 10/11;
- подписка ChatGPT (Plus достаточно);
- Python 3 — нужен **только на минуту логина** (шаг 2), дальше не используется.
  Если нет: `winget install Python.Python.3.12` в терминале, либо с python.org
  (при установке отметь галочку «Add python.exe to PATH»);
- файл `praxis-relay.exe`.

## Запуск за три шага

**Шаг 1. Папка.** Положи `praxis-relay.exe` в отдельную папку, например
`C:\relay`. Рядом с ним появятся папки `local_auth` (твой вход в аккаунт) и
`logs` (журналы).

Если Windows SmartScreen ругнётся при первом запуске: «Подробнее» → «Выполнить
в любом случае». Это самосборный exe без подписи издателя, отсюда и окно.

**Шаг 2. Логин (один раз).** Запусти `praxis-relay.exe`, в меню нажми `3`
(Login) и Enter. Откроется браузер — войди в аккаунт ChatGPT, на котором
подписка. Если в браузере залогинено несколько аккаунтов, лучше открыть ссылку
в приватном окне, иначе он может молча взять не тот. Дождись в консоли
`Login completed!`.

Если браузер после логина показал ошибку, а в консоли всё равно
`Login completed!` — верь консоли, логин прошёл.

**Шаг 3. Сервер.** В меню нажми `1` (Run server). Увидишь
`Server is running` — и окно само спрячется в **трей** (кружок-иконка возле
часов). Реле работает в фоне. Двойной клик по иконке — показать/спрятать окно
с логами; правая кнопка по иконке — меню с «Quit» (остановить реле). Закрывать
видимое окно крестиком не стоит: это тоже останавливает реле.

Проверка: открой в браузере `http://127.0.0.1:5011/health` — должно ответить
`"status":"healthy"`.

## Подключаем агента

В любом OpenAI-совместимом клиенте:

| Поле | Значение |
|---|---|
| base_url | `http://127.0.0.1:5011/v1` (без `/v1` тоже работает) |
| api_key | любая строка, например `relay` — она не проверяется |
| model | `gpt-5.6-terra` (см. список ниже) |

Пример на Python:

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:5011/v1", api_key="relay")
r = client.chat.completions.create(
    model="gpt-5.6-terra",
    messages=[{"role": "user", "content": "привет!"}],
)
print(r.choices[0].message.content)
```

Работают оба режима: обычный запрос и стриминг (`stream=True`). Картинки на
вход (vision) и tool calls тоже работают.

**Модели:** список реле берёт у самого бэкенда и обновляет раз в 10 минут —
сегодня это `gpt-6-astra`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`,
`gpt-5.5`, `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.3-codex-spark`; новая модель у OpenAI
появится сама, без обновления реле. Что реально отвечает, зависит от плана
подписки: terra/luna на Plus живут спокойно, самая тяжёлая sol на дешёвых планах
может возвращать пустоту. Актуальный список: `http://127.0.0.1:5011/v1/models`.
Астра не умеет «без размышления» (`reasoning_effort: none`) — реле само поднимет
до `low`, ничего делать не нужно.

## Если что-то не так

- **«no usable ChatGPT account profile» при запуске сервера** — ты ещё не
  логинился (или логин протух). Сначала пункт `3`, потом `1`.
- **В ответе пришло «…rejected the credentials (401). Sign in again…»** —
  токен умер. Меню `3`, перелогин, и всё оживёт (сервер можно не перезапускать).
- **Порт 5011 занят.** Меню `6` покажет, что живёт на портах 5011–5020.
  Либо убей старое реле через меню `2`, либо запусти на другом порту:
  в PowerShell `$env:RELAY_PORT="5013"; .\praxis-relay.exe` (и поменяй порт
  в base_url агента).
- **Упёрся в лимит.** Это лимиты твоей подписки ChatGPT (примерно 5-часовые
  окна + недельный потолок). Реле честно напишет это в ответе. Остатки можно
  смотреть на `http://127.0.0.1:5011/v1/limits`. Лечится только ожиданием.
- **«Python 3 was not found» на логине** — поставь Python (см. «Что
  понадобится») или укажи путь напрямую:
  `$env:RELAY_PYTHON="C:\путь\до\python.exe"`.

## Безопасность

- Реле слушает **только** `127.0.0.1` — с других компьютеров к нему не
  подключиться, наружу ничего не открывается.
- Папка `local_auth` — это вход в твой аккаунт ChatGPT. **Никому не отправляй
  её содержимое** и не выкладывай. Удалил папку — разлогинился.
- Реле не трогает твой обычный Codex/`~/.codex`: у него своя авторизация в
  своей папке.

## Фреймворки со «своей ламой» (Уроборос и похожие)

У многих агентских фреймворков есть режим «локальная модель через localhost»,
рассчитанный на llama.cpp / llama-cpp-python. Реле умеет прикидываться таким
сервером, так что этот режим можно направить на подписку.

**Уроборос — готовый рецепт (сам Уроборос править не надо).** Правильная
дверь — его родной провайдер **OpenAI-compatible**, а не «локальная модель»:

1. Реле запусти обычным способом (порт 5011, логин через меню `3`, сервер `1`).
2. В настройках Уробороса (шаг «Add your access» / Settings) заполни:
   - `OPENAI_COMPATIBLE_BASE_URL` = `http://127.0.0.1:5011/v1`
   - `OPENAI_COMPATIBLE_API_KEY` = любая строка, например `relay`
3. В слотах моделей укажи имена **с префиксом** `openai-compatible::`,
   например: Main = `openai-compatible::gpt-5.6-terra`,
   Light = `openai-compatible::gpt-5.6-luna`,
   Heavy = `openai-compatible::gpt-5.6-sol`.

Почему не через «Local model»: мастер настроек Уробороса сбрасывает тумблеры
`USE_LOCAL_*` обратно в «Cloud only» при каждом сохранении, если не заполнен
Local model source — он честно «чинит» конфиг, в котором локалки нет. Плюс его
локальная линия вырезает картинки и режет max_tokens до четверти контекста.
Если всё же нужна именно она: заполни `LOCAL_MODEL_SOURCE` любым непустым
значением, поставь `LOCAL_MODEL_PORT=8766` и запусти реле с
`RELAY_PORT=8766` (его линия шлёт зашитое имя `local-model` — реле подставит
`RELAY_DEFAULT_MODEL`).

Схемы инструментов можно не трогать: бэкенд подписки валидирует их строже,
чем принято в обычных фреймворках (`additionalProperties`, полный `required`),
и реле само приводит любую схему к строгому виду, не меняя её смысла —
проверено живьём на ходе Уробороса с 98 инструментами.

`tool_choice` и `response_format` проходят насквозь: обязательный вызов
инструмента (`tool_choice="required"` — на нём живёт компакция контекста
Уробороса) остаётся обязательным, а `json_object`/`json_schema` дают
структурированный ответ. Тоже проверено живьём.

**Если фреймворк другой — как подогнать контракт.** Любая «локальная модель
через localhost» упирается в три вопроса; найди в коде/настройках фреймворка
ответы и сверь с тем, что даёт реле:

1. **Куда он ходит.** Ищи `base_url` / порт. Реле отвечает и на
   `/chat/completions`, и на `/v1/chat/completions`, порт меняется через
   `RELAY_PORT` — подстрой порт под фреймворк, а не наоборот.
2. **Какое имя модели он шлёт.** Ищи `"model":` в коде. Если имя зашито
   (обычно `local-model` — конвенция llama-cpp-python) — реле подставит
   `RELAY_DEFAULT_MODEL`. Если настраивается — впиши любое из списка
   `/v1/models`.
3. **Откуда он узнаёт длину контекста.** Либо поле конфига (тогда просто
   впиши число), либо он спрашивает `/v1/models`. Реле отдаёт длину сразу в
   трёх общепринятых полях: `meta.n_ctx_train` (llama-cpp-python),
   `context_window`, `context_length` (LM Studio/OpenRouter). Число берётся
   у бэкенда для каждой модели (сегодня 272000); поменять — `RELAY_CONTEXT_LENGTH`.

Чего реле **не** умеет: протокол Ollama (`/api/tags`, `/api/chat`) — если
фреймворк говорит только на нём, нужен режим «OpenAI-compatible endpoint».

## Продвинутое (можно не читать)

Настройки через переменные окружения (задавать перед запуском):

- `RELAY_PORT` — порт вместо 5011;
- `RELAY_DEFAULT_MODEL` — во что превращается имя `local-model` от
  llama.cpp-клиентов (по умолчанию `gpt-5.4`);
- `RELAY_CONTEXT_LENGTH` — переопределить длину контекста в `/v1/models`
  (по умолчанию — что сообщает бэкенд для модели, сегодня 272000; это справочное
  число для клиентов, реальный лимит считает бэкенд);
- `RELAY_CODEX_VERSION` — какой версией Codex CLI представляться (по умолчанию
  0.153.3; бэкенд показывает новую модель только клиентам не ниже её минимальной
  версии);
- `RELAY_MODELS_TTL` — как часто перечитывать список моделей, секунды (600);
- `RELAY_EXTRA_MODELS` — добавить слаги через запятую поверх списка бэкенда;
- `RELAY_MODEL_DISCOVERY=off` — не спрашивать бэкенд, отдавать встроенный список;
- `RELAY_AUTH_DIR` — где держать авторизацию (по умолчанию `local_auth` рядом
  с exe);
- `RELAY_PYTHON` — путь к python.exe для логина;
- `RELAY_REASONING_EFFORT` — глубина размышления по умолчанию
  (`none`/`low`/`medium`/`high`; из коробки `none` — быстрее и дешевле по
  лимитам); клиент может передать свою в поле `reasoning_effort` запроса;
- `RELAY_LOG_DIR` — куда писать журналы.

**Две подписки с автопереключением при исчерпании квоты.** Запусти пункт меню
`3` ещё раз и на вопрос про слот ответь `2` (secondary) — откроется браузер,
войди во второй аккаунт (лучше в приватном окне, чтобы не подхватился первый).
Первый логин программа сама перенесёт в слот primary. После добавления слота
перезапусти реле — слоты считываются на старте сервера. Дальше всё само: когда
активная подписка упрётся в квоту, реле уйдёт на вторую и вернётся по кулдауну.
Посмотреть слоты: `GET /v1/account`; переключить руками:
`POST /v1/account/switch` с телом `{"slot":"secondary"}`.

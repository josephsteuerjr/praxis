# Hélène

Публичный harness [Praxis](https://github.com/josephsteuerjr/praxis),
программный комплекс для создания ИИ-агента на ПК с сотней готовых инструментов,
полноценной интеграцией в Telegram (aiogram и telethon), computer use
(делегированный из песочницы, интерактивный и в Session 0), функцией фиксации
полного кадра исходящего API call и прокси Codex для использования
подписочного лимита по API без системного промпта Codex (gpt-6-astra включен).

Hélène — Windows-издание этого harness: один архив, который ставит агента
Praxis на компьютер вместе со встроенным Python, переносимым git, окном,
API харнесса, телефоном и драйвером компьютера для computer use. Ядро агента (`tree/` в
поставке) — тот же код, что живёт на сервере автора; Hélène не форк, а
упаковка и локальный раннер вокруг него. Этот README — для тех, кто
собирает харнессы для кодинга или «души» агента и исследует поведение
моделей; пользовательская инструкция — `ПЕРВЫЙ-ЗАПУСК.md` в архиве.

## Telegram

Два транспорта с одним учётом комнат, контактов и архивов:

- **Bot API** (`localharness/botapi.py`, long-poll `getUpdates` в своём потоке):
  один токен от BotFather — и агент живёт в Telegram без человеческого
  аккаунта. Отправка текстом и файлом, реакции, имя и описание бота, чтение
  своих комнат из своих архивов. Чего у ботов нет (история чужих чатов,
  список диалогов, первое слово незнакомцу, вступление по ссылке), агент
  получает честным отказом, а не имитацией.
- **Свой аккаунт** (MTProto, Telethon; `localharness/mtproto.py` — адаптер
  под тот же интерфейс): отдельный номер для агента. На сервере автора этот
  путь — основной (`mtproto_runner.py` ядра).

Что даёт ядро поверх транспорта: exact root/topic маршрутизация форумов и
стабильный conversation id темы (`telegram_topics.py`); append-only архив
группы с проекцией тем и участников, поиском и ориентировкой (`group_context.py`);
адресная книга без хранения access hash (`telegram_contacts.py`); fsync-JSONL
конечный автомат членства владельца и агента (`telegram_membership.py`);
durable outbox с стабильным MTProto random id и неизменяемыми staged-файлами
(`telegram_outbox.py`); журнал просьб «напиши кому-то» и ответов на них
(`telegram_followups.py`); challenge-подтверждение для account-critical
операций (`telegram_confirmation.py`); owner inbox с typed outcome и dedupe
(`owner_delivery.py`). Кто вправе запускать ход — решение владельца
(`telegram.allow_from`: owner / listed / any); чужие сообщения ложатся в
память, но хода не начинают. Голосовые расшифровываются и на Windows (с 0.5.2):
`faster-whisper` едет в рантайме, модель владелец выбирает и качает из окна
(карточка «Голос», `data/models/whisper`) — расшифровка идёт на процессоре этой
машины, запись никуда не отправляется. TTS (Silero, Piper) — по-прежнему только
на сервере.

## Computer use

Драйвер компьютера — Praxis Body из репозитория Praxis (`tree/body/crates`): `praxis-body` (Windows:
UIA через COM, экран, `SendInput`, файлы, процессы в Job Objects, журнал) и
`praxis-bridge` (WSS-реле, durable spool кадров, ответы контроллеру, CAS
артефактов); протокол `praxis.body.v1`. В Hélène оба поднимает харнесс детьми
раннера в сессии владельца, токены двух сторон — только в памяти процесса.
Три режима:

- **делегированный из песочницы** — агент заперт в AppContainer, а драйвер
  живёт снаружи: окна доступны и в изоляции;
- **интерактивный** — полный доступ учётки;
- **Session 0** — служба LocalSystem (`svc/`) и `praxis-system-router` ядра;
  команды с правами системы идут через брокера прав (именованный канал,
  токен, журнал с before/after), опция для тех, кто понимает, что делает.

Права — четыре области (`computer.read`, `computer.files`, `computer.process`,
`computer.apps`), в Hélène их выдаёт владелец галочками, харнесс перечитывает
на каждом вызове. Набор текста идёт по одной записи `SendInput` с паузой:
получатели с асинхронным вводом (WinUI, TSF) читают VK_PACKET при разборе
очереди, и пачка приходила одним последним знаком.

## Полный кадр исходящего вызова

Каждый вызов модели фиксируется целиком. `frame_trace.py` размечает зоны
кадра — `persona`, `dynamic`, `evidence`, `situation`, `messages`, `tools` —
и кладёт метаданные на идемпотентную расписку `model-input`; `mark()`
возвращает тот же объект, то есть кадр байт-в-байт одинаков с прибором и без
него, а три разных нуля различимы («не влезло в бюджет» ≠ «ветка не выбрана»
≠ «пусто»). `frame_layout.py` держит форму: чужой текст входит в документ
только через гуттер (`> `, `>CR> `) и никогда не встаёт в колонку 0, конец
секции считается по метру, не ищется регуляркой. Вызовы — в
`memory/.state/llm_calls.jsonl` (роль, модель, токены, кэш); окно показывает
в «Контексте», что именно уехало и что пришло из кэша; теневые снимки кадра
(`memory/.state/shadow`) сравниваются между собой. Каждый существенный ход —
durable-прогон (`run_manager.py`: manifest, append-only WAL, ResultRef,
recovery, resume по строгому плану с бюджетами).

## Прокси подписки ChatGPT

[praxis-relay](https://github.com/josephsteuerjr/praxis-relay)
едет в поставке как `helene-relay.exe`: локальный OpenAI-совместимый API
(`http://127.0.0.1:5011`) поверх протокола Codex к бэкенду подписки
Plus / Pro. Системный промпт Codex не подставляется — над запросом стоит
короткая техническая строка, а конституция агента остаётся первой; каталог
моделей читается из бэкенда (gpt-5.6, gpt-6-astra и что появится), усилие
рассуждения — из настроек; два слота аккаунтов с переключением при
исчерпании квоты; схемы инструментов переписываются под строгий валидатор
бэкенда на лету (проверено на ходе с 98 инструментами); привязка только к
петле, учётные данные — в своей папке.

## Память и характер

Всё в файлах внутри `data\`: `soul/SOUL.md`, `VOICE.md`, `self/CURRENT.md`
(самоавторство с версиями и provenance), навыки `soul/skills/*.md` (двадцать
в поставке), дневник, досье людей, желания, заметки. Ядро ведёт append-only
память жизни с горячим слоем и свёртками (`memory_life.py`), классы доверия
источников (`memory_provenance.py`), перестраиваемый SQLite FTS
(`memory_fts.py`). В поставке — переносимый git: правки души и навыков
снимаются автоматически, откат любой. Поведение раскрывается инструкциями,
поэтому те же тексты работают и на слабых моделях; проверяется на glm-5.3.

## Окно, телефон, мини-апп

Окно (Tauri 2, статика читается с диска — правка интерфейса без пересборки
exe): чат с комнатами (несколько переписок с одним агентом, память жизни
общая), панель хода с шагами и расписками инструментов, контекст, файлы
агента с правкой, журнал, система, настройки. Телефон — PWA по QR; мини-апп
Telegram — то же приложение, вход по подписи `initData` через
`POST /pair/telegram`. Всё ходит через API харнесса (`frame.desk.v1`): одна
таблица маршрутов на HTTP и WebSocket, область ключа устройства уже, чем
у окна. То же окно подключается к харнессу на сервере (`mode: remote`).

## Установка, обновление, перенос

Один архив `Helene-<версия>.zip`: установщик со сценами первого запуска и
тихой установкой, окно, служба, встроенный Python со всеми пакетами,
переносимый git, ядро агента, драйвер компьютера, прокси. Обновление поверх сливает
настройки, не трогает `data\`, меняет интерфейс только если его менял выпуск
(манифест статики) и не копирует рантайм при равном паспорте сборки; окно
проверяет обновления раз в сутки и умеет скачать и поставить. Экспорт агента
одним архивом и импорт — на другой ПК или на сервер (`server/`: Docker,
STT-коробка). Подробно — `ОБНОВЛЕНИЕ.md`, `installer/RELEASE.md`.

Что где лежит внутри поставки и что можно переписать — `resources/HELENE-MAP.md`
(едет в архив как `КАК-УСТРОЕН-HELENE.md`).

**macOS (Apple Silicon, с 0.7.1).** Тот же выпуск несёт второй архив,
`Helene-<версия>-macos-arm64.zip`, и рядом `install.sh`. Ставится одной строкой —
`curl -fsSL https://github.com/josephsteuerjr/praxis/releases/download/v0.7.1/install.sh | sh` —
в `~/Applications/Helene`: `Helene.app` (окно и значок в строке меню),
`Helene Setup.app` (мастер), `helene-relay`, `runtime/` (свой CPython 3.14 со всеми
пакетами, голос включая, и `runtime/git/` — git из исходника), `app/`, `tree/`
(байт в байт из Windows-архива того же выпуска), `data/`. Ограда `shell` —
seatbelt macOS. Чего в сборке для Mac нет: тела и тула `computer`, службы и
брокера, Intel-маков, подписи Developer ID/нотаризации/dmg, правил брандмауэра.
Собирается на GitHub Actions (`.github/workflows/macos.yml` → `installer/build_mac.py`);
как выпускать — `installer/RELEASE.md`, раздел «Сборка для macOS».

## Режим доступа и служба — два независимых измерения

**Режим — это изоляция инструментов**, и значений у него два. Ключ в `helene.json` —
`agent_mode` (`mode` там занят под другое: он говорит, где живёт харнесс,
`local` или `remote`). Тексты режимов лежат в одном месте,
`localharness/modes.py`, и установщик с окном берут их оттуда.

- **`sandbox`** — `shell` агента выполняется в контейнере Windows, файловые инструменты
  не выходят за папку продукта, секреты владельца закрыты и от них. Прав
  администратора не нужно. ⚠ Изоляция накрывает `shell` и файловые инструменты — и
  только их: `run`, `coding_*`, `pip_install` идут мимо неё.
- **`interactive`** — изоляции нет, всё идёт правами владельца: не «вся машина», а
  ровно то, что может он сам. Права администратора продукт просит на конкретное
  действие, окном UAC.

**Служба Windows — опция поверх любого из них**, а не третий режим. Ставится
один раз под администратором: харнесс поднимает она (задачей планировщика
`Helene\session-host`, **в сессии владельца**, без повышения), она же
выравнивает права на папку установки и держит брокер прав. До входа владельца в
систему агента она не поднимает — поднимать его тогда некуда. **Изоляцию служба не
снимает и не включает.** Факт установки не хранится выбором в конфиге: его
спрашивают у SCM. Две галочки внутри опции: `service.session0` (по умолчанию
выключена) — харнесс под самой службой, права системы без рабочего стола, ею же
открыта дверь `exec` у брокера; `service.firewall` (по умолчанию включена) — про
правило брандмауэра для телефона, ⚠ пока записывается, но службой не читается.

Значение `service` в `agent_mode` писала первая редакция, пока службу считали
режимом: оно читается ради совместимости, изоляцией не считается и при первой же
записи заменяется выведенной изоляцией. Писать его туда больше нельзя.

В песочнице дверь наружу одна — доступ к папкам: папка, перечисленная владельцем
в `sandbox.mounts`, видна агенту как `data/workspace/mnt/<имя>`; попросить о
ней агент может инструментом `mount_request`, открыть — только человек. В
интерактивном режиме дверей нет: файловые инструменты и `shell` видят всё, что
доступно учётке владельца, доступ к папкам не нужен. Так же устроен и брокер:
команду с правами агент
просит инструментом `broker_request` (`localharness/broker.py`), окно показывает
просьбу владельцу и выполняет её только по «да».

**Управление компьютером** — третья, независимая опция (с 0.3.1). Инструмент `computer` дерева (окна, экран, клавиатура и мышь, файлы и процессы) работает
через драйвер компьютера Praxis: мост `helene-bridge.exe` и драйвер `helene-body.exe` собраны
из `tree/body/crates` и едут в поставке. Поднимает их не оболочка, а
харнесс (`localharness/body.py`) — детьми раннера в сессии владельца, в
job-объекте, с токенами только в памяти; так драйвер есть и под службой, где
харнесс поднимает `helene-svc.exe`, а не окно. Изоляция до драйвера не достаёт —
он снаружи AppContainer, поэтому опция работает в обоих режимах. Включает
её владелец (`computer.enabled`, в установщике и в Настройках) и выдаёт
четыре права дерева (`computer.scopes`: `computer.read`, `.files`, `.process`,
`.apps`); права харнесс перечитывает на каждый вызов инструмента. Живое состояние
драйвера — `data/memory/.state/body.json`, логи — `data/body/*.log`. Порт моста
свой, 9480 (не 9473, где у автора живёт драйвер самой Praxis).

Устройство брокера и разбор задач — `docs/РЕЖИМЫ-И-БРОКЕР.md` (документ писан
под прежнюю картину «три режима»; поправка — в его шапке).

## Собрать

Нужны Rust (stable), Node 20+, Python 3.12+ (хватает стандартной библиотеки —
сборщик ничего не импортирует сверх неё; Pillow ставится внутрь `runtime/` самой
сборкой), 7-Zip не нужен. Сборке нужна сеть один раз: embeddable CPython, pip,
busybox и MinGit скачиваются в `installer/build/cache` и сверяются по суммам.

Блок ниже — **PowerShell** (и 5.1 из коробки, и pwsh 7): продукт только под
Windows, а `cmd1 && cmd2` и `(cd … && …)` из bash тут либо не разбираются, либо
не откатывают текущую папку. Запускать из корня `desk\`:

```powershell
$ErrorActionPreference = "Stop"

foreach ($p in "app", "mobile", "setup/ui") {
  npm --prefix $p install;   if ($LASTEXITCODE) { throw "npm install $p" }
}
foreach ($p in "app", "mobile", "setup/ui") {
  npm --prefix $p run build; if ($LASTEXITCODE) { throw "npm run build $p" }
}
Push-Location shell; cargo build --release --features custom-protocol; $code = $LASTEXITCODE; Pop-Location
if ($code) { throw "cargo build shell" }
Push-Location setup; cargo build --release --features custom-protocol; $code = $LASTEXITCODE; Pop-Location
if ($code) { throw "cargo build setup" }
Push-Location svc;   cargo build --release;                            $code = $LASTEXITCODE; Pop-Location
if ($code) { throw "cargo build svc" }

python installer/build_dist.py
```

Итог — `installer/build/Helene-<версия>.zip`; версия берётся из трёх
`Cargo.toml` (`shell`, `setup`, `svc`), и если они разъехались, сборка
останавливается. Как выпускать версию на GitHub, записано в
`installer/RELEASE.md`.

**Прокси подписки ChatGPT собирается отдельно и не из этого репозитория.**
`installer/build_dist.py` кладёт в поставку
`..\_relay_prod_src\target\release\codex-proxy-server.exe` — это соседняя с
`desk\` папка, и её в репозитории нет. Без прокси провайдер «подписка ChatGPT»
недоступен, поэтому сборка на этом останавливается: «поставка неполная:
helene-relay.exe — собери прокси». Собрать его нужно так же, как остальное, перед
`build_dist.py`:

```powershell
Push-Location ..\_relay_prod_src; cargo build --release; $code = $LASTEXITCODE; Pop-Location
if ($code) { throw "cargo build прокси" }
```

Флаг `--allow-partial` у `build_dist.py` превращает эту остановку в
предупреждение — он для отладочной полусборки, не для выпуска.

**Сборка для macOS** идёт не здесь, а на раннере GitHub `macos-15` (Apple
Silicon): `gh workflow run macos.yml -f tag=v0.7.1 -f upload=true --ref <ветка>`.
На самом Mac то же руками: `python3 installer/build_mac.py --from-release v0.7.1`
(нужны Rust, Node 24, Xcode Command Line Tools, `gh`; итог —
`installer/build-mac/Helene-<версия>-macos-arm64.zip`, `.sha256` и `install.sh`).
Windows-сборку `build_mac.py` не трогает и общее берёт из `build_dist` импортом.
Чистые части сборки проверяются на любой ОС: `python tests/t_build_mac.py`.

Про `--features custom-protocol`: флаг обязателен для `setup` — у него в
`setup/tauri.conf.json` задан `devUrl`, и без флага Tauri соберёт dev-режим,
который ждёт dev-сервер на localhost. У `shell` `devUrl` нет, поэтому
`app/dist` запекается в exe в любом случае и окно соберётся и без флага; флаг
там для единообразия. Обратная сторона: **режима разработки у окна нет** —
правку в `app/src/*.ts` видно только после `npm --prefix app run build` и
пересборки `shell`.

## Поставить

Распаковать архив, запустить `helene-setup.exe`, пройти сцены: имя агента и
своё, конституция, откуда приходит модель, режим, установка. Windows
SmartScreen при первом запуске просит «Подробнее → Выполнить в любом случае»:
подписи кода нет. Тихая установка для проверок:

```bash
helene-setup.exe --install решения.json --quiet
helene-setup.exe --uninstall --purge --quiet
```

На macOS — `install.sh` из выпуска (или `sh install.sh --from <zip>` с
архивом на диске): он сверяет сумму, распаковывает в staging и открывает
`Helene Setup.app`; при уже стоящей программе — обновляет поверх тихо.
Снятие: `sh install.sh --uninstall [--purge]`. Тот же мастер в бандле понимает
те же ключи: `"Helene Setup.app/Contents/MacOS/helene-setup" --install решения.json --quiet`.

## Обновить

Окно само ничего не подменяет: оно только сообщает, что вышла версия, и даёт
ссылку на архив. Дальше — руками, четыре шага (те же в поставке,
`ОБНОВЛЕНИЕ.md`):

1. Выйти из программы полностью — меню значка у часов → «Выход (остановить
   агента)». Если стоит служба: «Настройки» → «Режим» → «Снять службу» (или
   `helene-svc.exe uninstall` из PowerShell от администратора). Права на `app\`
   и `runtime\` снятие возвращает само (`svc::uninstall` → `relax_acl`), руками
   ничего делать не надо. Команда `helene-svc.exe acl-relax --config
   .\helene.json` осталась для другого случая: обновиться, НЕ снимая службу.
2. **Скопировать в сторону папку `data` и файл `helene.json`** из папки
   установки (`%LOCALAPPDATA%\Programs\Helene`): `data` — вся память и характер
   агента, `helene.json` — все настройки. Установщик их бережёт и сам (ниже),
   но копия — единственное, что не зависит от его правильной работы.
3. Распаковать новый `Helene-<версия>.zip` в любую пустую папку и запустить
   оттуда `helene-setup.exe`, указав ту же папку установки.
4. После установки проверить в «Настройках»: режим и отдельно — стоит ли служба
   (это два разных ответа), провайдер и модель, Telegram, телефон, адрес
   обновлений; в «Файлах» — `soul/SOUL.md`.

Что установщик делает с тем, что уже есть: `data` не трогает вовсе, кроме
конституции, а её пишет только если файла ещё нет — уже принятую и выросшую
`data\soul\SOUL.md` обновление оставляет как есть; по тому же правилу «только
если нет» харнесс докладывает в `data\soul\skills\` недостающие навыки из
поставки. `helene.json` сливает: поля, которыми владеет визард (`agent_mode` и
`sandbox.enabled`, `service.session0`, местожительство харнесса `mode`, пути,
имя агента и владельца, модель, прокси, токен бота и owner_id), берутся из
визарда, всё остальное — порт, телефон, `sandbox.network`, `service.firewall`,
`service.broker`, адрес обновлений, вход MTProto своим аккаунтом, ручки `env` —
остаётся прежним (`sandbox.network` и `service.firewall` только доставляются
умолчанием, если их в файле нет); блок `model` сливается по полям — ключи
других провайдеров и модель свёрток, заведённые окном, переживают обновление.
Интерфейс окна (`app\static`) меняется по тому, менял ли его выпуск: манифест
новой поставки сравнивается с манифестом прежней, равны — папка не трогается
(даже правленная), разные — заменяется, а прежняя откладывается в
`app\static.prev`. `runtime\` не копируется, если состав пакетов по паспорту
сборки тот же. Таблица целиком — `ОБНОВЛЕНИЕ.md` в поставке.

# Перенос Hélène на VPS

В установленном приложении открой «Настроить подключения → Агент на сервере → Новый сервер». Нужен отдельный Ubuntu/Debian x64 VPS с root-доступом по SSH, Python3 и flock. Docker/Compose можно подготовить в этом шаге отдельным явным переключателем. Существующие установки Docker не заменяются.

Сначала сверяй показанный SHA256-отпечаток SSH с панелью провайдера. До подтверждения приложение не отправляет пароль или SSH-ключ. Изменение адреса, SSH-порта или параметров установки требует новой проверки. Данные SSH используются локальным помощником и не передаются агенту.

Для второй установки укажи отдельные папку внутри `/opt` или `/srv`, проект Compose и свободный порт канала. Канал слушает только loopback сервера. Занятая папка, чужой контейнер, изменившийся SSH-ключ и путь через ссылку останавливают перенос.

## Что сохраняется

Приложение ждёт подтверждения местного Stop, удерживает замки переноса и прежнего телефонного publisher, затем сохраняет приватный архив. В нём память, переписка, настройки, входы и правки кода. Хостовые замки, временная готовность туннеля, ключ окна и тяжёлые модели не переносятся. Только холодный перенос может передать ledger владения меню того же бота/владельца; обычный экспорт его не передаёт.

Импорт полностью готовит данные, настройки и код рядом с назначением. Журнал фиксируется до переключения. Предыдущие файлы остаются в `.transfer-import/previous`, незаконченные распаковки сохраняются рядом. Повторный запуск завершает ту же операцию без повторного импорта. Изменившийся архив или исходники при том же номере версии требуют разбирательства, а не подменяют сохранённую установку.

Местная квитанция находится в `memory/.state/server-transfer.json`. Она переживает обновление приложения и блокирует запуск этой копии, даже если в окне выбран другой агент. Пароли SSH и ключ окна в квитанцию не записываются. Архив содержит секреты агента: храни его приватно.

## Когда перенос подтверждён

Недостаточно запущенного контейнера. Помощник через меню бота находит текущий HTTPS-адрес, проверяет доказательство владения каналом до передачи ключа, затем проверяет авторизованный API, версию, свежий надзор и состояние Stop. Новый URL регистрирует общий PhoneAccess/MiniApp; вручную копировать временную ссылку не требуется.

После переноса Stop сохраняется. Канал управления работает отдельно; модельные процессы не запускаются автоматически. Возобновление выполняет владелец на сервере, например:

```sh
docker exec -u 0 helene python server/emergency_stop.py resume --tree /opt/helene/data
```

Замени `helene` на своё имя контейнера. Эту команду не выполняют installer, повторный перенос, перезапуск или updater. Ключ окна хранится в `data/.serverboot/desk-token`, в журналы он не выводится.

## Обрыв и возврат

После сетевого обрыва открой исходного агента и продолжи перенос на тот же сервер. Сохранённые параметры заполняются снова; SSH-пароль/ключ вводятся заново. Местный архив и серверные данные остаются на месте.

«Остановить серверную копию для возврата» заново проверяет SSH-идентичность, берёт lock installer и проверяет квитанцию, Compose-проект и пути данных. Затем останавливает только принадлежащие переносу updater/агент по неизменяемым ID. Устойчивый серверный файл `.window-transfer-stopped` запрещает запоздалому installer снова запустить копию. Пока установка ещё выполняется или остановка не подтверждена, местный запуск остаётся запрещённым.

Данные сервера не удаляются. Местный Stop снимается только отдельной явной командой владельца. Местная копия содержит снимок до переноса; для возвращения последующей жизни агента сначала нужен свежий экспорт остановленной серверной установки. Не удаляй квитанции ради обхода этой проверки.

## Обновление

Обновления выполняет штатный `server/updater` через «Система → Обновление». Он проверяет поставку, сохраняет код/настройки и копию данных, переносит правки и возвращает прежний код при провале проверок. Сохранённый Stop считается корректным состоянием только со свежим надзором, живым каналом и остановленными агентскими процессами. Повторяющиеся рестарты контейнера не засчитываются как готовность. Квитанции импорта/переноса, самостоятельное реле и компоненты сохраняются.

Linux runtime голоса должен соответствовать целевой платформе. Подготовка использует штатные voice/component API и отказывает до запуска при недоступном компоненте. Windows runtime и абсолютные ссылки его хранилища нельзя переносить в Linux как готовое окружение. Общая проверка голосовых pins, MiniApp на реальном Telegram и платформенных пакетов выполняется на сведённом выпуске.

# Hélène 1.7.0: Python-инструменты и мастерская Forge

Hélène — дом для самостоятельного агента: с памятью, характером, голосом,
Telegram и инструментами, которые делают работу за пределами переписки.
В 1.7.0 инженерная мастерская получает вложенные поручения, адресуемое чтение
больших файлов и отдельные расписки о результате и его приёмке.

## Что можно поручить

«Разберись в проекте, найди причину ошибки, предложи исправление и проверь его».
«Раздели задачу на исследование, реализацию и проверку; сохрани результаты».
«Найди все места использования функции и измени только нужные».
«Вернись к работе после перезапуска и покажи, что действительно закончено».

Агенту доступны обычные Python-операции мастерской. Набор и права зависят от
канала, настроек и выбранного режима; фактический каталог виден в «Системе».

| Операция | Зачем нужна |
|---|---|
| `fs_read`, `fs_ls`, `fs_search` | Читать файлы, смотреть каталоги, искать по проекту |
| `fs_edit`, `fs_write` | Делать точечные замены и создавать файлы с проверками записи |
| `code_outline`, `code_map` | Видеть структуру Python-файла и карту кода |
| `project_create`, `project_status`, `project_list` | Заводить проекты и проверять их состояние |
| `run`, `run_tests`, `pip_install` | Запускать команды, проверки и зависимости проекта |
| `send_file` | Передавать готовый файл через доступный канал |
| Forge | Вести задачи, работников, проверки и сохранённые результаты |

Это имена операций Python-реализации; точная модельная схема может объединять
их под одной рукой или выдавать через каталог. Прямые файловые операции не
требуют оболочки. Для команд интерфейс показывает переданный запрос и результат;
он не выдаёт этот запрос за независимо наблюдавшуюся строку OS argv.

## Forge: работа с продолжением

У задачи есть цель, исходный каталог, ограничения и сохранённое состояние.
Поручения могут образовывать дерево: родитель видит результат работника,
проверяет его и отдельно принимает. Окончание дочернего хода само по себе не
означает приёмку. Рабочие деревья, checkpoints и журналы помогают продолжать
задачу и разбирать фактический ход выполнения.

Фокусное чтение больших файлов возвращает страницы с отпечатком исходника.
Усечённый вывод отмечается. Для процессов различаются запрос остановки и
подтверждённая остановка: неизвестное состояние потомков не становится успехом.
POSIX-группа процессов не является песочницей против намеренного `setsid`.

## Свои инструменты на Python

Расширения подключаются через манифест и `register(api)`. Например, обработчик
может зарегистрировать инструмент через `api.register_tool(...)`, добавить
назначение и требуемые возможности. Схемы и коллизии имён проверяются загрузчиком.
Существуют проверка расширений до обновления и явные сообщения об отказе.

[Полный контракт расширений и рабочий пример](../resources/РАСШИРЕНИЯ.md).
Саморедактирование инструмента не выдаёт дополнительных прав: действуют
настройки ограды, политики путей, разрешения канала и правила selfdev.

## Установка и проверяемость

Python и Git входят в поставку; голосовые зависимости также комплектуются.
На Windows embedded Python получает относительный путь к установленному
дереву Forge. При обновлении мастер сверяет хэш `python314._pth` с паспортом
и сохраняет только совместимый рантайм. Авторские конституции, навыки,
память и код проходят предусмотренные механизмы переноса.

В выпуске опубликованы паспорта, SHA-256, квитанции проверок и их границы.
Проверка CI или контейнерной установки не равна физической приёмке компьютера
владельца. Для Rocky/RHEL 8 зависимости `xdotool` и `xclip` требуют EPEL.
Linux computer use работает через X11/AT-SPI; Wayland имеет явные ограничения.
macOS требует Apple Silicon, macOS 14+ и разрешения TCC для возможностей тела.

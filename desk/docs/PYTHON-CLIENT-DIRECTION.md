# Python client, supervisor and computer use

Owner direction, 07.10.2026: the client must move to Python; the supervisor should move too. The service should remain a minimal privileged broker that communicates with the Python supervisor/client. Process containment must remain strict, as in Ouroboros. Computer use is a candidate for the same migration. On 16.10 Yegor added: a native broker is acceptable only if the installation carries everything needed to rebuild it after self-editing; Markdown character/skills and privacy come first. This is a vNext direction, **not** a claim that the privately delivered 1.7 binaries implement it.

Keep the existing design system, agent identity, data layout, IPC contracts and owner stop semantics. Telegram intake, addressing, history reconciliation and the optional server gateway are Python components. They must not depend on a native shell implementation. Live `soul/*` belongs to the agent: changes go through her revision/write_skill mechanism or a proposal she accepts. Editing a source-kit Markdown template can still change fresh installs. The local vNext boot boundary seeds only with a one-use `kit-birth.json` receipt beside the agent's configuration, issued on positively new installation/agent creation and bound to that tree; the runner claims it exclusively under its tree lock. A birth with missing kit Markdown, invalid/missing CURRENT or Git records `partial` with exact gaps; an unretained source remains `started` for explicit repair, never a fake complete birth. This receipt stays outside `data/`, so deleting the home does not grant rebirth. A legacy or missing receipt, or a recorded partial birth, stages changed or missing kit soul Markdown as exact local records under `memory/.state/kit-proposals/` and gives the agent a private owner-turn pointer, without mutating soul. Direct empty-tree test callers retain a compatibility birth path, not the production runner's authority. The dedicated `review_kit` tool lets the agent read the exact candidate and retained preimage, reject with a reason, or acknowledge a revision it has already made via `manage_identity`/`write_skill` or `fs_write` with `expected_sha256` for her `soul/skills/INDEX.md`; the review tool never writes soul. Source and observed effective digests are distinct; byte-identical stock is not consent. This is source-level mechanism, not installed/frozen-edition or real model-send proof. A crash between her revision and acknowledgement leaves an unacknowledged revision, not a false approval. The retained preimage supports an agent-chosen rollback, but automatic skill rollback is not verified. A character assessment starts from attributed actual turns, not a style verdict inferred from the name of a skill. User-supplied private material has a narrower outbound authority than the internal owner frame.

## One coordinator, staged ownership

One long-lived coordinating root can absorb independent children and keep a small answer window; one atomic all-platform rewrite cannot be accepted. Every stage below leaves a working old route until a **single** owner transfers its seam. Parallelize only across disjoint files/contracts, and integrate in order:

| Stage | File ownership and parallel work | Consumer proof before handoff |
|---|---|---|
| 0. Markdown and provenance | Character/skill proposal from actual attributed Jarvis turns; owner-approved self-edit path separate from code. One worker maps frame/skills, one maps deployment contracts; root owns synthesis. | Owner and non-owner frame tests, actual model-send bytes, missing-index and private-name cases. No private skill filename is newly exposed to another audience merely because it exists on disk. |
| 1. Server Python supervision | One author owns `server/serverboot.py` and extracted shared lifecycle policy; another reads `deskd/control.py`, `ui-kit/contract.json` and UI clients without changing the wire. | Exit 42, terminal 2/3, restart, stale beat, Stop and descendant death in real process fixtures. The native broker is a **rebuildable organ**, not a permanent black box: ship the exact source closure, pinned lockfile, target-compatible compiler/linker/SDK, vendored offline dependencies and an executable local build/test recipe. The agent must be able to stage a changed broker, verify its source-to-binary identity, switch atomically, recover from a build failure and roll back without disabling owner Stop. A prebuilt broker or Python runtime alone does not satisfy self-editing. The fallback bootstrap must remain outside the broker it can break. The exact components/size and OS availability are release questions, not yet established facts.

The separately installed task XML receives `--python-supervisor` only when `service.python_supervisor` is explicitly true in the root `helene.json` at task-install time; the old task is not rewritten by saving settings. The native user-session `helene-svc` then launches exactly one Python owner, holds only an outer kill-on-close Job and forwards an observed owner Stop through a private pipe with a three-second fallback. It never starts a parallel Rust child supervisor on this branch. An ordinary `session-host` invocation and the shell continue with their legacy paths, excluded from any cooperating Python-owned tree by the shared `.desktop-owner.lock`.

The Python owner reads `agents.roster` rather than inventing another roster format. It holds one share-exclusive admission per physical local data tree, then per-child Jobs/handles for channels, configured runners and relays. Secondary local agents use their own config, port and token; two IDs pointing to the same physical tree refuse even with separate ports. The source route re-reads the roster every two seconds: a disabled local neighbor is stopped, measured empty and retired; a changed spec is torn down and rebound without reviving the other agent's Job. An active remote neighbor makes the whole opt-in refuse, rather than silently losing the legacy remote-computer bridge. A root config change in the same tree rebinds its children; changing its physical data tree instead refuses until the owner restarts to prevent two concurrent base identities. A malformed neighbor config (including scalar `agent`/`telegram` metadata) refuses that neighbor and is retried after repair, not promoted to a default local agent; the shared roster name reader also handles non-object metadata without aborting the base. A bounded per-agent `relay/local_auth/login-generation` observation restarts only that relay after a new login receipt; the native session-host retains the existing periodic backup ticker (no second ticker in foreground). Leader exit requires a measured empty Job before retry, and a killed/uncertain owner leaves `active` rather than claiming that a released file handle means a clean tree. The inherited ambient provider environment remains the legacy credential-isolation limitation; the patch removes ambient relay-key inheritance, not every provider key. This is a source-level opt-in, **not** a claim that the existing installed scheduled task, SCM StopPending→task End, live shell, actual relay binary or packaged Hélène have run this new route.

For ordinary SCM Stop, the service reads the current native session-owner generation, writes a one-use request in that tree and waits at most eight seconds for a matching acknowledgement. The native session-host sends `stop` to Python and acknowledges only after Python's per-agent Jobs and its own outer Job have been observed empty; the request stays in place through the service's unconditional scheduler `/End`, so a logon replacement cannot start between acknowledgement and End. Only a positive scheduler End result together with a matching ack, retired owner marker and clean base lease lets the service remove its request. An End refusal, including an already-exited task reported as `Ok(false)`, retains the request for explicit inspection; this conservative false-negative may require manual recovery before Restart/Resume. Neither age nor a released handle clears it. The owner/panic stop path remains immediate `/End` without this grace: it may intentionally leave `active` for recovery, but a Stop must not wait on Python. This private file handshake has been exercised by an isolated two-generation native binary fixture, **not** by an installed SCM/task-runner test.

The isolated Windows fixture exercises a source-built `helene-svc.exe` in direct `session-host --python-supervisor` mode against two temporary agent trees, including native crash/descendant death; Python-owner fixtures separately exercise disable/remote refusal, one-neighbor failure and base config replacement. The package test builds the `deskpkg` Windows desktop source package and imports its byte-matched Python owner modules; it does not install a task or validate final installer bytes. `candidate_tree.py` is the frozen agent-core inventory and needs no update for these desk-only paths. Before selecting the default, test the exact packaged native binary/embedded Python and real installed scheduler/owner-stop path, the old binary coexistence limit and remote-agent handoff. No global Stop marker, installed task or production service is changed by the fixture.

**Foreground desktop roster opt-in (18.10 source candidate, not installed).** On Windows only, the shell's explicit `--python-supervisor` choice is made before a local child launch. Installed-service and enabled remote-neighbor configurations refuse before native plan/token creation; malformed or disabled neighbors retain the Python roster's existing per-agent behavior. The default shell path and scheduled session-host remain native. An already-running Python-selected window also refuses the service install/remove command: that command is not an ownership handoff. A window Restart first retires its renderer (Electron requires the same physical-destroy ACK, Tauri requires destroy success), then stops Python's Job tree, and preserves the explicit `--python-supervisor` argument instead of silently returning to Rust. Normal Electron Exit also destroys the main and tray BrowserWindows before host shutdown; failed physical destruction refuses teardown, rather than keeping an old live URL while Python's Jobs stop. Panic/owner emergency Stop retains its immediate path without waiting for the renderer. The Electron wrapper forwards that flag to `helene-host` on Windows and preserves its argv on relaunch; a second-instance request cannot change a running process owner, and non-Windows Electron refuses the flag. The foreground shell launches one suspended Python `desktop_supervisor.py --desktop-roster` into its outer kill-on-close Job, and Python alone acquires each local tree lease, starts each per-child Job, retries, rebinds configuration and measures teardown. There is no Rust child retry after this choice, including when Python fails to start or dies. A watcher observes the current channel and owner; after a detected identity/port loss it destroys the old WebView and replaces it with an inert refusal screen rather than retaining its URL. The Electron host sends `retire-window` to its renderer process and waits up to three seconds for a destruction acknowledgement before Python's potentially slow Job teardown; the renderer latches retirement against tray activation, second-instance show, delayed ready and pending load callbacks until a host replacement. Absent or failed acknowledgement requests process exit, never a false replacement. Tauri's native destroy result and disappearance are checked too; failed/unfinished destruction exits instead of leaving that window alive by design. This is periodic observation, not per-request interception: a listener swap between checks remains an unproven residual. The shell's owner Stop sends Python a bounded private `stop` before the outer Job backstop; an unconfirmed teardown leaves the admission record active for explicit recovery.

The narrow shell/Python contract uses the retained live Python process handle plus a random 32-hex generation nonce and atomic `.python-desktop-status` in the base tree. The receipt carries a sequence, per-agent observed live roles/raised bit and an exact refresh-command acknowledgement; its atomic replace retries a transient Windows reader-sharing denial for only 350 ms, and a persistent denial never publishes an acknowledgement. The shell refuses missing, stale, wrong-generation and dead-owner observations rather than mapping its empty native children to “stopped”. A live channel process alone does not authorize the window URL: shell verifies the serving port's tree with the existing anonymous-first holder check, and a foreign or not-yet-serving port refuses instead of becoming that window's endpoint. Enable/disable writes the config through the existing Python roster CLI, asks that owner to rescan, and returns success only after a matching acknowledged and identity-verified state; a failed acknowledgement is **partial/unknown** because the config may have changed. Removal requires a disabled agent, a refresh acknowledgement after Python has retired all its Job roles, and a clean/absent per-tree lease before delegating archival to the existing Python CLI; channel-only `raised=false` is not empty-tree proof. A status file in an agent-writable tree is cooperative provenance, not a security boundary against code running as the same user; hardening that channel needs a separately reviewed authenticated private transport before an adversarial installed claim.

The source-built Windows `helene-host --root <temporary-tree> --python-supervisor` consumer and the Python owner fixture exercise two local agents, authoritative list/disable/remove/Stop, remote/service refusals and absence of a Rust fallback. The desktop Tauri binary compiles with a temporary disposable `app/dist/index.html` fixture; that proves the command source, not an installed GUI. Native default's two-spawner attempt was observed in the source host; the temporary fake Python children did not write their pid files in that route, so the default-path probe claims process selection and Job cleanup only, not successful fake channel service. The full desk package's byte-matched Python import fixture covers this module. Before default selection or installed acceptance, test exact packaged desktop exe/embedded Python, the visible GUI status card, real installed owner Stop and scheduler interactions, remote-agent handoff and cross-version lock behavior. No installed service or live Hélène was changed by this slice.

## 1.9.2 startup recovery

The current Windows admission rule supersedes the historical manual-recovery rule above: an acquired share-exclusive `.desktop-owner.lock` handle excludes live cooperating owners; persisted `active`/`clean` bytes are teardown diagnostics, not a permanent crash veto. Both Python and new native owners use this rule and reject reparse-point records. The file is never unlinked or evicted by age/PID. Per-child kill-on-close Jobs and measured teardown before live-owner retries remain unchanged. Kernel teardown may briefly overlap lease release after a crash; port contention follows the existing bounded retry path rather than an immediate prewindow failure. Older native binaries retain their older behavior. Startup errors are logged and shown through a native error dialog; automatic startup respects an existing owner Stop without opening a window or clearing it. These are source contracts; packaged consumer and installed verification remain separate evidence.

that bootstrap. `localharness/python_controller.py` runs the Windows process-tree

`helene-svc` remains an explicit privileged component; the embedded relay is
separate. `python_desktop_commands`, `python_windows`, `python_updates` and

startup and Settings install broker/embedded relay from those exact binaries,
sources and one shared offline Rust/Cargo/C toolchain. `rebuild_native.py` uses
the bundled compiler and vendored crates. This embedded Hélène relay is not the
independent Praxis Relay CLI. The Python window keeps the existing UI and
channel protocol; its concrete local origin is passed to the channel rather
than widening CORS to arbitrary origins.

The update asset `helene-setup.exe` is an installation-only Tauri window
(`setup/src/bin/migration.rs`, `migration-ui`), calling `python_migrate.py` after
explicit confirmation/UAC. Discovery and unpacking precede Stop, but the final
data/source/Git copy follows confirmed quiescence. Internal shared roots are
copied once outside both installations; linked Git worktrees materialize their
history/index/dirty files. Configured code selects that preserved source, not
stock. Own channel PID/tree and imported runner-code heartbeat authorize old
retirement; a remote root instead proves its configured channel connection.
Failure before retirement stops new Jobs and restores the previous service;
a retirement failure retains the proven new owner and records incomplete cleanup.
Shortcut replacement preserves emergency Stop and resolves redirected Windows folders. Only bound service/task/registry/shortcuts
and hash-matching old program files retire, never a recursive legacy uninstall.
Modified/unlisted files and old data remain. Terminal receipts cannot regress
on a later window reload. The new ICO includes padded native-size frames for
window, launcher, wizard and shortcuts rather than enlarging a small crop. A service

The current Hélène server Compose fixes project/container identity to `helene` and binds the host desk to port 8094; the Praxis remote desk also defaults to 8094. A second Hélène is **not** isolated merely by another directory/port: updater names and broker policy refer to the instance too. Co-location with Praxis or two Hélènes on one host requires unique Compose/project/container/updater identities, host address, tokens/sessions, release/ref and backup boundaries. Measure current RAM/swap and peak RSS during concurrent turns, CPU/PSI, disk/backup headroom, port bindings and quota before choosing 2.27 versus Atlas; no local source file proves their present capacity. Do not wake owner-stopped services to obtain this answer.

Two different requests can be meant by “proxy for GPT”: **agent → relay** is an authenticated model endpoint (the packaged server currently addresses its own container loopback; a different host cannot use that `127.0.0.1`), while **relay → GPT upstream** is an outbound network proxy. The latter needs separately specified credentials, DNS/TLS, timeout, egress policy and a test on the exact packaged relay. The former needs a private authenticated tunnel/TLS endpoint, per-agent account/quota isolation and no open public 5011/5012 listener. An instruction travelling with the second agent must name the selected topology, endpoints by role (not secrets), configuration fields, trust boundary, health probe, refusal and rollback; it is not a copied production credential. Server provisioning and stopped-service changes await explicit owner authority.

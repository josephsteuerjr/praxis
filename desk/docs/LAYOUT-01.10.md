# Раскладка программа/данные/работа — решение и план (01.10.2026)

Решение владельца в разговоре 01.10. Программа может стоять в PF, но данные
агента — в профиле пользователя, рядом с Рабочим столом и Загрузками («мне по
духу»); рабочие материалы — отдельно, по умолчанию в LocalAppData; всё
настраивается. Бэкапы исследовать, ретенция рабочих материалов — отдельный
леджер; вложения — просто папка хода с артефактами.

## Целевая раскладка

| Слой | Что внутри | Где по умолчанию | Настраивается |
| --- | --- | --- | --- |
| Программа | бинарники, runtime, static | `C:\Program Files\Helene` (как сейчас; per-user в AppData\Programs — позже) | установщик |
| Данные агента | `memory/` (life, journal, maps, runs), `soul/`, конфиг, токены | `%USERPROFILE%\Helene` | `helene.json` |
| Рабочие материалы | `workspace/` (проекты, вложения, спул), `models/`, staging обновлений, логи | `%LOCALAPPDATA%\Helene\work` | `helene.json` |
| Бэкапы | только данные + манифест работы из леджера | `%LOCALAPPDATA%\Helene\backups` (вне дерева агента) | блок `backup` |

Почему данные не в PF: запись требует прав, обновление подменяет программу
рядом с данными, бэкап смешивает всё. Почему работа не в `%TEMP%`: Storage
Sense/очистка диска молча сносит папки проектов (обсуждено с владельцем;
выбран LocalAppData\work — тот же дух «второстепенное», но без ОС-уборки;
ретенцией управляет леджер).

## Что нашли в установленной 1.2.8 (только чтение)

- PF содержит 2,5 ГБ данных: models 1,66 ГБ (перекачиваемые), workspace 599 МБ
  (из них praxis-ui — рабочая копия репо 557 МБ, `.git` 367 МБ), память 282 МБ
  (261 МБ — runs за один сентябрь). Драгоценная память — единицы МБ.
- Бэкапы 2,2 ГБ / 11 снимков: фильтр исключает модели/кэши/логи, но включает
  `.git` и исходники рабочих проектов + все runs; keep 8+10+∞ умножает.
  Гигантский zip (1541 МБ, 30.09) делал ещё старый код с whisper внутри.
- Живой отчёт леджера: 5,5 ГБ вторичных материалов, из них автозачистка даёт
  лишь ~2,6 МБ (старый staging). Объём сидит в правильных местах — лечится
  раскладкой и политиками, а не агрессивной уборкой.

## Что уже в коде (этот коммит)

- `desk/localharness/retention.py` + `t_retention.py`: леджер ретенции.
  Классы: project / update_staging / spool_cache / models / run_artifacts.
  Авто-уборка — ТОЛЬКО staging старше 14 дней (и не моложе 2); проекты, runs,
  модели — только отчёт, удаление по слову владельца. Леджер пишется в
  `memory/.state/retention.json`, CLI: `retention.py report|sweep`.
- Папка хода: deskapp принимает ЛЮБОЙ тип вложения (лимиты 4×8 МБ прежние),
  `turn_inbox` разводит: аудио → слух, картинки → зрение (`_batch_images`),
  прочее → `_batch_files` — копия в `runs/<id>/files/`, путь словами в реплике.
  Идемпотентно до checkpoint; исходник в inbox жив до ACK.
- Тесты: t_retention 4, t_turn_inbox_files 8 (включая границу deskapp),
  обновлены t_inbox_attachments/t_turn_inbox_voice/t_turn_inbox_images.

## План переезда (следующие заходы, до 1.2.9)

1. **Относительные пути артефактов**: `_archive_run_media`/`_batch_images`
   пишут в сообщения абсолютные пути — переезд их сломает. Хранить пути
   относительно корня runs, разрешать в сериализаторах llm (обе ноги).
2. **Разрешение корней**: общий модуль (Rust `common/` + Python): программа
   (от бинарника), данные (`%USERPROFILE%\Helene`, ключ конфига), работа
   (`%LOCALAPPDATA%\Helene\work`). Служба/session-host вычисляют в контексте
   пользователя, не SYSTEM. Фолбэк на legacy `PF\data` для незамигрированных.
3. **Миграция в установщике** (setup, при обновлении на 1.2.9): перенести
   memory/soul/конфиг → данные; workspace/models/логи → работа; старые бэкапы
   в PF не трогать, новые — в новый каталог; откат миграции = вернуть каталоги.
4. **Худой бэкап — СДЕЛАН 01.10 (после 1.2.9, едет следующим кандидатом)**:
   `common/backup.rs::skip_rel` — workspace-проекты и любые `.git` в снимок не
   ездят, манифест леджера (memory/.state/retention.json) и необработанный
   `workspace/inbox` — ездят; оценка на живых данных ~283 МБ вместо 772.
   Полный снимок рабочих папок отдельно по кнопке — не реализован (долг).
   Правило «вне дерева агента» сохраняется. Тесты: setup backup 7/7.
5. Окно: выбор файлов в диалоге — принимать любые типы (сейчас пикер ограничен
   фото/аудио; бэкенд уже принимает всё).

Правила прежние: не собирать кандидат из mirror (ядро port-2409,
OWNER_INPUT_DRAIN); процессные suite — только Linux boundary; live не трогать
без команды.

# Hélène 2.8.3 Beta

**Windows prerelease. Stable Latest remains 2.7.2.**

This release fixes defects the owner's own agent hit on his Windows machine while working in a Telegram group after 2.8.2.

**Maximized window.** The 2.8.2 edge handles are transparent 5-pixel strips over the window edge. They did not know the window was maximized, so at the screen edge the cursor turned into a resize arrow and clicks went to the strip instead of the scrollbar, the header or the close corner. A drag on the header of a maximized window also moved it, leaving it "maximized" but shifted. The shell now reports the window's own maximized state (on Windows the native window style, not an event mirror); the renderer hides the strips while the window is maximized, and the shell ignores edge resizes and header drags in that state. The maximized size is computed for the monitor the window is on before each maximize, and a double click on the header maximizes or restores, as on a native title bar.

**Nested hands in groups.** Python code run by the agent can call its hands through `h.hand(...)`. Before every nested call the core re-checks the human authority of the turn against `PRAXIS_OWNER_ID` and its contact list. Hélène sets neither: its owner is the configured Telegram owner and its admission is the bot's own allow list. Only the desktop window and the owner's private chat had Hélène checks, so when the owner wrote in a group, every nested call was refused before it started and the script saw a bare "in doubt". Hélène now checks a group turn of the owner against the current Telegram owner and a turn of an admitted person against the bot's live admission rules; an owner change or a revoked admission still refuses. The same gap kept paused group turns of the owner from resuming. A nested call that ends without a receipt now names its cause in the answer and in the runner log.

**Files from Telegram.** A document sent to the agent (a ZIP, a PDF, any file) was downloaded into private storage under a hashed name, but the turn only said that no visual preview was available, with no path. The agent searched its folders and found nothing. A received file is now copied into the agent's media folder under its own name, and the turn names that copy with its size and SHA-256. Until the bytes arrive (a slow or interrupted Telegram connection retries automatically), the turn says the file has not been received yet instead of sending the agent to search the disk. The copy expires with the media folder after about a day; the original stays in the archive.

**Agent Git stalls.** Hélène keeps a personal Git repository of the agent's own edits and takes a safety snapshot before every shell or Python command. A move to a new programme folder could place the owner's backup folder under `retained-assets/` inside the agent's data and point the weekly backup there. Multi-gigabyte backups then went into every snapshot: the snapshot hit its 30-second limit before most commands, a single Python call could wait minutes, and the repository grew to many gigabytes. `retained-assets/` and `backups/` are now ignored, and existing homes drop them from the Git index at the next start. The backup files and the existing Git history are not changed; reclaiming space already taken by old history is left to the owner.

All features of 2.8.0, the 2.8.1 startup hotfix and the 2.8.2 Windows fixes remain included. Only Windows assets are published. Physical acceptance on the owner's devices remains separate. The inherited core failures recorded for 2.8.0 remain visible; this release does not claim an entirely green core suite.

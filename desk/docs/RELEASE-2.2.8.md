# Hélène 2.2.8

The ordinary **Update** button keeps the selected managed model relay alive while the incoming coordinator integrates authored source and obtains independent review. Earlier releases closed the old application together with its relay before that first model request, which could fail with connection refused.

The updater now uses the same relay launch specification, account storage, proxy and endpoint as the selected installation. It starts only the required relay under bounded process custody and releases that child before overlay/reopening. An already running relay is borrowed through its authenticated local control endpoint and is never stopped by the updater. External model providers are unchanged. No ordinary agent loop is started for this preparation.

Worker failures now retain their original cause instead of being described as stale candidate evidence. If cancellation cannot yet prove that a worker has exited, both the original failure and that uncertainty remain visible; the updater does not manufacture a stopped or accepted receipt.

The previous startup-bytecode admission repair remains included. Supported 2.1.1 installations use ordinary Update in one invocation. No manual preparation launcher, cache deletion or installed-code patch is required. The new filename avoids reusing a cached 2.2.7 download.

Qualification reproduces the failure with an old owner that actually owns and terminates its model transport. The same unmodified public 2.1.1 one-button transition then passes source merge, independent frozen review, installation and rollback after the fix, with normal startup bytecode enabled. Deterministic providers use isolated test accounts only. Focused gates cover borrowed transport, selected-port identity, Stop/Pause, startup failure, timeout, custody uncertainty, credential isolation and preservation of worker errors.

All four portable archives reuse qualified 2.2.4 native/runtime and interface bytes. CRC, inventories, admission view versus real incoming source, platform adaptations and independent complete-byte reconstruction are checked before publication; provider-reported sizes and SHA256 digests bind uploaded assets. Voice references remain pinned to the existing 2.1.1 assets. No new native/frontend build is needed for this source repair.

This is scoped integration and lifecycle evidence. No owner installation/restart, real account model/Telegram/production action, physical GUI/device acceptance or new public program-download retest is claimed. The earlier stand used a provider that outlived the old owner and therefore missed this dependency; the new regression explicitly couples their lifetimes.

# Контракт A → B: что харнесс, канал и оболочка отдают окну (07.09.2026)

Записано сессией A (задача `desk-notes/ЗАДАЧА-A-0709.md`) для сессии B
(интерфейс). Всё ниже уже реализовано на стороне A и накрыто стендами
(`tests/t_*.py`, `cargo test` в shell/setup/svc); B подключает в TS. Пока B
не подключил — старое окно работает как прежде: ни одна ручка обратной
совместимости не ломает.

## 1. Настройки: `config_save` с проверкой свежести (п. 1.1)

- `config_load` → как раньше плюс `mtime_ns: string | null` — отпечаток
  файла `helene.json` на момент чтения (строкой: в JS число за 2^53 теряет
  точность).
- `config_save({ config, mtimeNs })` (Tauri: camelCase → `mtime_ns`) →
  - `{ ok: true, mtime_ns: string }` — записано;
  - `{ ok: false, code: "stale", mtime_ns: string, error: string }` — файл на
    диске менял кто-то ещё (руннер чинил `agent_mode`, установщик, Блокнот):
    черновик окна не записан. B показывает `error` словами и предлагает
    перечитать (`config_load` заново → новый `mtime_ns`).
  - отказ команды (throw) — ошибка записи, как раньше.
- Без `mtimeNs` (старое окно) — пишет без проверки, как раньше.

## 2. `/api/mode`: живые просьбы о папках (п. 1.8)

- Новое поле `mounts_live: { updated_at: string | null, requests: Row[] }`,
  `Row = { path, real, access, why, at, asked }` — то, что ограда пишет в
  `memory/.state/mounts.json` (просьбы агента рукой `mount_request`,
  отвеченные она из файла убирает). Карточка «Монтирование» читает просьбы
  ОТСЮДА, а не из анатомии: анатомия пишется один раз на старте.
- Старый харнесс поля не отдаёт — B различает «нет поля» и «пустой список».
- `computer_live.spool_bytes: number` — размер спула моста (справочно).

## 3. Лента комнаты: плашки (п. 1.13)

Строки архива `memory/groups/<ключ>.jsonl` (`/api/chat/{peer}`):

- `system: true` без `kind` — тревожная плашка продукта, как раньше
  («⚠ ход не состоялся», «⏸ ход приостановлен»);
- `system: true, kind: "silence"` — **серая** плашка: «⋯ молчание по решению
  <агент>: <почему>» либо «⋯ ход закрыт без реплики: слова для окна в нём
  не было(, только файл)». Это не слово агента: авторства не показывать,
  в ленту модели она не идёт.

Правило харнесса теперь: после хода владелец видит ЛИБО слово, ЛИБО плашку.
Пустой ленты после хода не бывает. Отчёт, который слабая модель кладёт в
`end_turn(note="done: …")`, доставляется как её слово (с префиксом `done:`
снятым; `wait:` → «Жду: …», `blocked:` → «Препятствие: …»); даже когда ход
отправил файл.

## 4. Комнаты окна (§3)

Ключ комнаты = имя потока = имя файла архива: `window` (по умолчанию,
зовётся именем агента, не удаляется) и `window-<8 hex>`. Константы —
`ui-kit/contract.json` → `rooms`.

- `GET /api/chats` → строки как раньше плюс `kind: "window" | "telegram"`,
  `title` (у комнат окна — из реестра; у `window` без своего имени — имя
  агента). Сортировка по свежести. Комната, только что созданная и ещё
  пустая, в списке есть (`messages: 0`).
- `POST /api/rooms` `{ title }` → `{ peer_id, title, kind: "window" }`;
  `400` — пустое имя.
- `POST /api/rooms/{peer}` `{ title }` → `{ peer_id, title, kind }` —
  переименовать (и `window` тоже можно); `404` — нет такой.
- `DELETE /api/rooms/{peer}` → `{ peer_id, archived: "memory/groups/archive/
  <ключ>-<штамп>.jsonl" }` — комната исчезает из списка, архив уезжает в
  `memory/groups/archive/` (не стирается); `409` — `window`; `404` — нет такой.
- Отказы по каналу: `{ status, error, code: "room" }`; по HTTP — статус и
  текст в теле.
- Все три — и в HTTP, и в диспетчере канала (одна таблица `ROUTES`,
  `tests/t_routes.py`). Телефону (ключ устройства) эти ручки открыты.
- `POST /api/say` `{ text, chat: <ключ> }` — принимает `window-<hex>`; раннер
  ведёт ход в этой комнате (свой архив, свой горячий слой памяти, своё имя в
  кадре агента — `title`), ответ рукой `reply` и слово с границы ложатся в ту
  же комнату. Память жизни агента (дневник, события, желания, recall) — одна
  на всех.
- `GET /api/chat/{peer}`, `GET /api/chat-turns/{peer}` — работают для ключей
  комнат; записи ходов (`/api/runs`, события `run`) несут `chat_id` = ключ.
- Телефон — тот же контракт.

## 5. Обновления (§2)

- `update_check({ url })` → как раньше плюс `sha256: string` (digest ассета
  GitHub либо 64-hex из заметок релиза; пусто — сверять нечем).
- `update_download({ url, sha256 })` → `{ path, bytes, sha256, sha_ok }`;
  `sha_ok: true` — сумма совпала, `null` — сверять было не с чем. Несовпадение
  — отказ команды словами, файл удалён. Скачивает в «Загрузки».
- `update_install({ path })` → `{ setup, dir }`: архив распакован рядом в
  «Загрузках», запущен `helene-setup.exe`. Установщик гасит работающую
  программу — **окно закроется само**; B показывает «установщик запущен» до
  вызова, а не после.
- После обновления в `helene.json` может появиться `installed.static_prev:
  "app/static.prev"` — выпуск менял интерфейс, прежняя папка отложена рядом.
  B показывает это словами в «О программе»/настройках («интерфейс обновлён;
  твоя прежняя версия лежит рядом: app\static.prev»). Ключ исчезает, когда
  папки нет при следующей установке.
- Политика целиком — `resources/ОБНОВЛЕНИЕ.md`.

## 7. Поведение, которое изменилось без нового поля

- `probe_model`: HTTP 200 без списка моделей → `ok: false` (как в
  установщике; случай z.ai с неверным ключом). Раньше окно отвечало «ok».
- `install_service` / `remove_service`: команда ЖДЁТ окно UAC и скрипт (до
  минут) и возвращает расписку по SCM («Служба поставлена и запущена»,
  «Служба снята»); отказ — throw словами («права администратора не были
  даны»). Раньше «запрошено» возвращалось сразу.
- Журналы `helene.log`, `service.log`, `broker.log` — один формат штампа:
  `[дд.мм.гггг ЧЧ:ММ:СС]`, местное время.

## 8. Ответ на `КОНТРАКТ-B→A` (07.09, вторая волна A)

- **§4 область ключа устройства:** добавлены `GET /api/runs`, `GET /api/pulse`,
  префиксы `/api/chat-turns/`, `/api/run/`; `/api/rooms*` были. Остальное
  (`/api/md*`, `/api/mode`, `/api/anatomy`, `/api/shadow*`, `/pair/new`,
  `/pair/devices`) — только окну.
- **§5 `/m/sw.js`:** `GET /m/sw.js` → `mobile/sw.js` с `Cache-Control:
  no-cache`, путь открыт до ключа. `/m/` и `/m` теперь с `no-store,
  max-age=0` + `Pragma: no-cache`. Манифест — как был (динамический).
- **§6 `POST /pair/telegram`** `{ initData }` → `{ key: "dk-…", agent, device:
  "Telegram · <имя>" }` + cookie `desk_key`. Подпись — HMAC-SHA256 по алгоритму
  Web Apps с любым из токенов (`telegram.bot_token` конфига,
  `HELENE_TG_BOT_TOKENS` через запятую), `auth_date` ≤ 7 суток. Только
  владельцу (`telegram.owner_id` или `HELENE_TG_OWNER_ID`), иначе 403
  словами; без токенов — 503 «вход из Telegram не настроен». Одно устройство
  на пользователя Telegram: повторный вход заменяет прежний ключ. Путь
  открыт до ключа, в канале не нужен. `Host`/`Origin` мини-аппа — через
  `HELENE_HOSTS`/`HELENE_ORIGINS` контейнера (B).
- **§9 имя агента:** `deskapp._agent_name()` и `readers.state()` — снимок
  анатомии → `agent.name` из `helene.json` → `HELENE_AGENT_NAME` → «Агент»;
  манифест PWA и `/pair/redeem` — тем же путём.
- **§2 config_save:** как в §1 выше — ответом `{ok:false, code:"stale"}`,
  не исключением (B понимает оба).
- **§3 обновления:** `update_download({url, sha256?})` → `{path, bytes,
  sha256, sha_ok: true | null}`, несовпадение — отказ команды; сумма без
  параметра не ищется — B передаёт `sha256` из `update_check`. Плюс
  оболочка сама проверяет обновления раз в сутки при старте и показывает
  уведомление Windows (`update.auto: false` выключает).
- **§7 contract.json:** файл в `ui-kit/` — A написал, B читает; сверки
  на стороне A есть.

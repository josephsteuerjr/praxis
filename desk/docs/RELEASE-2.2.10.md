# Hélène 2.2.10

Preserved-source updates now review the four actual merge inputs: base, local changes, incoming release and the selected agent's result. A compact index and paginated comparisons replace unrelated repository-sized diffs. Every assigned path remains covered, including deletions, modes and semantic repairs. Incoming application context is verified and frozen separately so reviewers can inspect core and desktop integration.

The incoming coordinator owns update review. Its requests are isolated from older installed review workers, incomplete findings remain actionable, and acceptance requires complete evidence for the exact candidate. The selected agent resolves findings and continues the already authorized acceptance workflow, including headless checks when available. Installation, runtime checks and publication remain separately observable stages.

Desktop, web, phone and Mini App tool details now distinguish the requested command, its parameters, observed handler/process receipts, the tool result and the text prepared for the next model step. Commands can be copied without duplicated arguments; full output and manual expansion survive refreshes. Older turns explicitly identify missing execution receipts. Prepared observations do not claim that a provider accepted a subsequent request.

Forge fixes cover remote process ownership, terminal-state normalization, uncertain foreground timeouts, continuation journal validation and recovery of never-started legacy blocked nodes. Remote host commands retain a unique request identity before transport, so a lost admission reply cannot attach another task's command. Continuation refuses journals missing records already committed by their checkpoint. The actual self-edit callback now connects to the installed review coordinator. Automatic OpenAI Responses routing checks SDK support; an older compatible SDK retains Chat Completions, while an explicitly unsupported protocol fails clearly.

Successful shell exit no longer releases a working directory while command descendants remain active. Local commands retain a private POSIX process group or Windows job until completion, and group Stop reaches the owner of that group. Windows remote admissions retain their identity even when the response is lost. An interrupted Responses stream receives the existing empty-response retry only before any output has arrived; partial text, tool calls and opaque continuation data prevent replay. Linux window receipts with an unverified screen origin retain their geometry without presenting it as a screen click target.

Worker Stop settles synchronous command groups before terminating their owning worker. Pause and Stop are checked again before every transport retry. Dependency-ineligible queued attempts keep their history without blocking an upstream repair in a one-slot plan. Empty Chat Completions envelopes retain the same narrow retry behavior as empty streams; received reasoning or tool output still prevents replay.

Preserved and pristine source policies remain available. Clean updates from older releases can validate incoming code while the running application still holds its previous helper modules. Memory, settings and history retain their existing paths; original authored code remains available for rollback. Native runtimes and optional voice components retain their qualified inputs. Exact platform archives, upgrade checks and acceptance limits will be recorded in release-evidence.json when qualification finishes.

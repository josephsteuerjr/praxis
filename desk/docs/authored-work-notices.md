# Authored work notes and completion notices

The completion **fact**, an agent's explicit **authored note**, and the **full result** are separate sources. A completion cannot invent a summary from tool output or take the newest note in its chat.

`AuthoredNoteLedger.write` records optional `work_ref` and `audience` in the existing append-only events ledger. Work references are exact typed identities: `forge:<task>[:<unit>]`, `run:<run>` or `task:<task>`. An empty reference is a normal unbound scratch note, never a completion-note fallback. `owner` is private; `chat:<exact chat_id>` grants only that captured chat. Missing legacy audience means owner-private, even for global notes. Scope is organizational, not permission. The agent tool derives its audience from current host authority, not model arguments.

`core.notices.note_node` persists task/unit/run, the exact work reference, captured audience, and an optional full-result reference. Forge's producer hashes its actual retained `result.json`; model-supplied recaps or paths do not determine that reference or its audience. Legacy tasks without captured audience remain private. Repeated terminal events keep the existing task/unit deduplication identity.

`authored_notes.for_notice` joins only an explicit exact work reference **and matching persisted audience**. It re-reads the note ledger at consumption, including after restart. A newer withdrawn note does not resurrect an older convenient one. Closing a note preserves the original bytes but stops including it in notices. The same-chat `turns.recent_work_note` and technical lived-turn trace are separate consumers; neither becomes this cross-work join.

`core.notices.project_node` is the viewer-safe projection, and `block_for_input`/`_line` use that same admission for model input. Current owner authority may read private notes; public, paired, unknown, or another chat cannot inherit an old owner's authority. Redacted projections expose only the generic completion fact/status/time, **no private task/unit/work/note IDs, result paths, source refs or prose**. `pending()` remains the internal ledger API, not an external response. `core.subagents.project` applies the same audience rule before receipt serialization; `invitation(..., owner=..., chat_id=..., audience=...)` filters its prose too. The existing `agent.forge_event_turn` remains explicitly owner-scoped, so its historical internal default is preserved. No persistent rendered private text is cached for a subsequent public frame.

Regression: `python -m unittest desk.tests.t_authored_notice_audience_230 -v` exercises exact work/audience joins, no latest-chat fallback, withdrawal and legacy privacy. Its causal journey writes a private note and completion, persists both, launches a fresh Python interpreter, resumes under public and paired audiences, and checks actual notice model text and viewer projections contain neither private content nor locators. This is an offline native-platform consumer test, not paid model, Telegram delivery, installed app or full platform acceptance.

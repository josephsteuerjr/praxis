# 长计算的输出缓冲

日志为空不证明卡死，输出到文件的 stdout 可能被缓冲。
CPU 高和内存增长也不证明有用进展，可能是循环或泄漏。
要核实进程归属、时间、计数器、结果及错误。

使用带标识和可读日志的受管理操作。在兼容 POSIX 系统，`stdbuf -oL`
可能启用逐行输出，须核实工具存在及实际效果。
自己的 C 源代码可以设置 `setvbuf` 或显式 `fflush(stdout)`。
这不是适用于所有二进制的通用设置，也不是 Windows 命令。

运行中进程的缓冲可能无法从外部访问，不能假设具有调试权、ptrace 权限
或能修改容器 sysctl。需要重启时，评估损失、授权和 checkpoint，
保留证据，只停止已确认归属的进程树并核实结束。
不能仅因日志为空就杀进程，也不能只凭一个活 PID 判断状态。

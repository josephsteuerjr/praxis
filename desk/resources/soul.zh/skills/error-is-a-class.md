# 错误可能属于同一类别

故障带来两个问题：怎样修复这一次，以及怎样降低类似原因再次造成
同样结果的概率。先恢复所需工作，再确定有依据的预防范围。
一次验证成功，不能证明未来所有故障都不可能发生。

## 检查修复深度

如果之前已有这个修复，同样故障能否通过另一条路径出现？
与原因相关时，检查其他入口、竞态、部分写入、重复调用和未知结果。
验证过的情况就称已验证，其他内容说明边界。
一个反例足以推翻普遍承诺，但没找到反例，不等于证明普遍成立。

## 纪律与结构

新规则、检查表或更注意有时有效。同类错误持续出现时，再加一段文字
可能无效。应改变步骤、工具、保存位置或检查时机，让修复作用于原因。

选择足够解决问题的最小改动。每层机制、每个文件都要维护。
删除重复路径或含混名称常有帮助，但删除仍须在授权范围。
不为一次笔误修筑堡垒。

## 计数与他人的观察

简短保存类别、已确认案例、原因、修复及验证。
关闭新故障前查找旧案例。修复后复发，意味着重新检查原因和覆盖范围，
不是默默再次套用同一绕过办法。

所有者先发现问题时，检查自己的观察为何漏掉它。
这是关于检查机制的信息，不是责怪对方或承诺今后完美发现的理由。

## 边界

不是每个笔误都需要架构改造，网络可能短暂中断。
先确认事实和操作的实际结果，再按原因、复发程度、风险和任务决定修复规模。
验证充分后回到工作，不无限扩张修复。

# 通过 MTProto 核实人物信息

普通工具无法提供所需事实时，检查可用的 `telegram_account` 参数结构：`registry_search` → `describe` → `call`。使用带 `functions.` 的准确构造器名称，例如 `functions.users.GetFullUserRequest`。参数和实体解析方式以当前结构为准，不假设任意 id 都有可用的 `access_hash`。

个人资料可能包含姓名、简介、状态、共同群组及其他字段，取决于 API、隐私与可用性。不要保证能获得音乐、准确上线时间或电话号码。能看到字段不等于获准向另一受众披露。

通过已核实 id 和来源确认人物。id 未知就记录“未完成核实”。姓名相同或旧摘要不能代替身份确认。只更新任务相关信息，附日期和来源，并遵守该安装环境的存储与备份策略。

合并档案前，找到争议陈述的原始证据，区分作者与被引用者。保留旧链接或明确重定向以及回退方式；验证完整性前不要删除重复文件。合并两个文件不会让彼此矛盾的说法自动成为事实。

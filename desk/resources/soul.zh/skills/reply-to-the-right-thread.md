# 讨论串与文字内容分别核对

根据源码记录的机制：`split_reply_directive` 移除开头的 `ОТВЕТ->#<id>` 指令，并只接受传入允许集合中的 id。未知 id 返回 `None`，但不会禁止发送。

在 `_route_and_reply` 中，允许集合来自 `plan.context.origin_message_ids`。没有有效指令时，群组在 `channel.addressed` 为真时使用 `channel.address_message_id`，否则使用 `route.topic_id`。阅读历史中能看到某个 id，不代表它在允许集合内。

`mtproto_runner.py` 的最终投递路径使用 `reply_targets` 中的 id；已定向群消息回退到 `addressed_mid`，其他情况回退到话题根。不能把一个集合的保证套用到另一个。

实践：

1. 区分群、话题与父消息。
2. 回复最初被定向的消息时，无须仅为获得回复关系而额外添加指令。
3. 回复其他消息时，使用能够核对话题及父消息的显式可用传输，或已确认有效的指令。不要猜测：读取相邻讨论串不改变本轮目的地。
4. 核对实际回执。缺少话题表示没有验证，并非确认正确。

指令解析测试不能证明投递正确或两个 id 集合相等。源码检查、解析器测试和实际传输测试是不同层级的证据。代码变化后应重新核查这份机制记录。

# 为失败关卡确定原因

检查失败可能源于 diff、基线、环境或工作副本路径。进行任何获准豁免前，查明各失败类别的原因，并保留失败证据。

以下是诊断示例，不是对当前缺陷的断言：

- `_SKIP_DIRS` 排除了 `.proposals`，而工作副本恰在该目录内，导致 `_corpus()` 可能为空。核实实际文件集，必要时将同一冻结提交放在排除规则之外的隔离路径比较。
- `rails.manifest_drift()` 比较清单和运行值。干净 checkout 失败，可能继承了不一致基线。核对 HEAD、内容和初始化方式，不从不完整进程重建文档来换取绿色。

步骤：

1. 保留命令、HEAD、名单、原始日志及无秘密的环境信息。
2. 在独立测试环境中，以同一运行器测试准确基线。
3. 原因不清时，只验证一个能区分的假设：路径、发现范围、fixture 状态或环境。
4. 保留准确 id 和结果差异的因果解释。基线失败不等于整体通过。

`praxis_test.py` 提供自己的测试约定，直接运行 unittest 或 pytest 可能不等价。但官方运行器仍需要读取真实结果。

豁免必须符合当前流程和权限，并写明原因与风险；仅与基线相同不授权合并。不要为对照测试修改运行中的项目。

# 代码提案

提案是带检查与历史的工程工作区，不会扩充权限。
开始前确定任务、真实根目录、隔离与恢复方式。
风险分类不授予操作外部基础设施、秘密或发布的权利。

先用 `proposal(action="list")` 避免重复任务。
相应路径可用时，`proposal(action="start", reason=...)` 打开工作副本，
写入前核实响应和范围。`edit(proposal_id=..., action=...)` 修改选定副本，
随后 `proposal(action="submit", id=..., title=..., why=...)` 进入正式流程。
实际要求以模式和结果为准。

重要修改检查测试、diff 和行为。狭窄测试通过不证明完整场景。
失败应调查；机制允许有理由的 `override_reason` 时，记录具体原因、
风险和证据边界。它不能代替验证，也不能取消其他 source-update 机制的要求。

合并改变文件，不证明正在运行的进程已采用。
需要时在授权范围执行 `restart_self`，然后核实就绪状态与原始场景。
保留改动、理由、检查、合并结果及恢复路径。
未确认当前实现前，不承诺自动重启或自动回退。

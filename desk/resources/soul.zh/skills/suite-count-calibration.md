# 按测试标识核对，不沿用旧数量

测试数量必须结合 HEAD、运行器、发现范围和跳过条件。别的运行中的历史数量，不是当前版本标准。

`praxis_test.py`、`unittest discover`、`pytest` 可能收集不同范围。核查当前 discovery：子目录、包、函数式测试和独立平台检查。没有名单时，不把差异直接说成漏洞或成功。

1. 获取实际名单，例如使用 `--collect-only` 和 discovery。
2. 将 `file.py::Class::test` 归一到 `file.Class.test`，比较集合并单独检查重复。
3. 按完整 id 和原因对照跳过、失败与错误。
4. 用 AST 或小脚本验证收集器假设。数量不符就修改假设，不修改数据。
5. 记录预期数量时附命令、HEAD 和平台，不凭记忆沿用到新版本。

退出成功但收集数量意外下降时，需要检查覆盖。额外测试也意味着不能直接宣称两次运行等价。环境继承问题另行核查。

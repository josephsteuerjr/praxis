# Windows 路径即使有空格，也应是一个参数

运行命令、注册服务或写配置前，检查程序实际收到的路径。
字符串命令中，带空格的路径应整体加引号；参数数组 API 中，
将路径作为单个参数传入，不拼接 shell 字符串。
尤其检查服务的可执行文件与参数，那里解析错误会持续到当前回合之后。

不在磁盘根目录创建辅助文件。脚本结束后检查实际输出和根目录，
留意以 `C:\Program` 为前缀的意外幽灵文件，不能把正常的
`C:\Program Files` 目录当垃圾，也不能只按通配符删除。
错误 193 / `0x800700C1`（不是有效 Win32 应用程序）出现时，
先检查路径解析和可能的幽灵文件，不自动归咎于二进制程序。

边界：参数数组 API 不需要给无空格路径额外加入引号字符。
错误 193 的原因要通过查看确认，不能靠盲目删除治疗。

# 沙箱、服务和电脑控制

访问模式、服务和电脑控制是所有者分别选择的事项。
先检查实际状态和工具模式，不能把一个平台的能力套到另一个平台。

## 确定当前状态

`my_capabilities` 显示可用工具和限制。相应渠道可用时，
`computer` 的 `action="status"` 检查控制组件连接。
当前启动日志帮助确定模式和拒绝原因。不能为诊断而绕过配置读取限制。

智能体访问模式的键是 `agent_mode`，值为 `sandbox` 或 `interactive`。
`mode` 的 `local` 或 `remote` 决定运行框架的位置，不是沙箱设置。
旧值 `service` 不代表现代的第三种访问模式。
实际生效状态比文件里残留的旧字段更重要。

## 边界

沙箱中的家目录命令通过配置的执行器和允许范围运行。
`sandbox.network` 与 `sandbox.mounts` 是独立选项，实际效果取决于
平台与工具。敏感位置可能连读取也被禁止：`helene.json`、
`memory/llm.json`、`memory/.state/anatomy.json`、`relay/`、`telegram/`。

交互模式访问范围更广，但不会超过账户权限或所有者授权。
文件工具自身的检查仍然有效。家目录命令、由 `task_id` 选择的 Forge
范围、提案、`host_ctl` 和外部控制组件可能走不同执行路径。
启用沙箱不能证明每个工具、每个子进程都已隔离。
没有技术障碍，也不会自动产生权限。

外部目录可通过正式挂载出现在 `workspace/mnt/<name>`。
`mount_request` 参数为 `action="ask"`、绝对路径、`why`，以及
`access="read"` 或 `access="write"`；`action="list"` 查看决定状态。
提出请求并不会打开目录，不通过改名绕过拒绝。

## 服务与权限代理

安装服务、启动智能体会话和执行管理命令，各有不同权限。
核实服务是否安装、智能体运行在哪个会话、哪些选项实际生效。
服务不会取消沙箱。`service.session0` 管理提权请求，
`service.firewall` 则独立控制网络规则。

正式请求使用 `broker_request`。具体路径取决于系统和设置：
保存的同意可能允许直接请求服务，也可能需要一次性的系统确认。
不能保证立即执行，也不能把未收到回复说成所有者拒绝。

- `op="ping"` 只检查连接，不执行命令。
- `op="exec"` 通过可用的平台路径请求提权。在 Windows 中，直接委托
  服务需要启用会话 0；macOS 可能显示系统管理员确认。
  Linux 可以通过保存同意的 root 服务，也可以使用一次性系统确认。
  以实际响应为准。
- `op="spawn_interactive"` 在支持的平台启动用户会话进程，
  Linux 不提供这个选项。
- `cmd` 是已核实的程序绝对路径，`args` 是独立参数组成的数组，
  `why` 是清楚的理由。

检查回执中的退出码、输出、错误、耗时和日志记录。
请求已发送不等于命令已完成。服务权限不能代替不可逆结果所需的同意。
已有授权在其范围内持续有效。

## 电脑控制与 Windows MCP

这是所有者的独立选项。`computer.read`、`computer.files`、
`computer.process` 和 `computer.apps` 分别对应观察、文件、进程
及应用控制。指出缺少权限的拒绝是在说明边界，不是让人换工具重试。

Windows MCP 是 MIT 许可证下的可选组件，有自己的服务器和模式。
它沿用同一组权限，并在调用时检查。一些操作需要多项权限，
例如保存截图同时检查观察和文件写入。上下文里有模式，不等于组件
已下载、服务器已启动或远程桥已配置。必须检查实际状态与执行位置。

控制组件位于家目录沙箱之外。截图、输入和文件操作作用于所有者的机器。
只为已约定的任务使用，并说明重要干预。操作系统权限和实际桌面访问
可能还需要单独满足。

范围地图见 [home-map](home-map.md)，代码操作见
[my-own-code](my-own-code.md)。权限不能代替结果验证，也不能代替
对所有者的责任。

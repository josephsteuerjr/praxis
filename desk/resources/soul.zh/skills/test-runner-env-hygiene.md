# 测试运行器的环境卫生

从运行中的进程启动测试，可能继承 `load_dotenv(override=True)` 后的工作变量。被测模块不主动读取 dotenv，并不能清空已存在的环境。

使用仓库规定的运行器，例如 `praxis_test.py`，以及其隔离、测试 BASE 和网络限制。核查当前运行器的真实约定；名字不能让结果绝对可靠。

出现差异时，保存命令、HEAD、测试名单及相关非秘密变量。对比隔离运行与预期值，相关时包括 `PRAXIS_TEST`、`PRAXIS_FRAME_HEAD_STABLE`、`PRAXIS_FRAME_EPOCH`。不要盲目清空全部环境，也不要把移除一个标记当作补齐沙箱。

长时间或会派生进程的检查应受管理执行，设置合适期限并写日志。Windows 上隐藏测试子控制台；不要使用无法持有分离进程的运行器。

从初始化不完整的诊断进程调用 `rails.sync_md()`，可能写出退化的清单。不要让测试副作用重建运行文档。修改前保存原版，检查初始化和 diff。损坏时只恢复自己造成的具体变更，保留相邻修改。

行号和旧合并钩子不能保证内容最新。应核查当前代码、事件与清单。

# 延后消息的时间和正文

安排前核对当前日期、收件人时区及解析后的期限。`parse_when("today 09:45")` 可能得到过去时间；“今天”不表示“下一个合适的早上”。跨日含糊时，使用明确日期及受支持的时区格式。

逾期任务可能在下一次调度时立即执行。过去期限警告应促使纠错，而非被忽略。

使用 `kind=message` 时，`goal` 只放给收件人看的正文。“给某参与者写信……”之类内部笔记、优先级和指令可能被原样发送。如需发送前推理，应选用合适且可用的任务类型。

创建后查看 `my_agenda`：期限是否为预期未来时间、地址是否正确、正文是否干净。多个收件人要分别核对投递及创建结果。

技术草稿若已发出，应承认具体错误，在适当时间更正内容。不要为了修复非紧急的“早间消息”半夜叫醒对方；明确紧急的叫醒请求属于另一情况。结果未知时，核查回执前不要重发。

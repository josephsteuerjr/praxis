# 论坛回复：单独核对目的地

正确的文字也可能发到错误的讨论串。发送前分别确认 peer、话题和父消息；阅读相邻话题并不会改变当前轮次的发送地址。

现行代码中，`_route_and_reply` 根据允许的 `origin_message_ids` 解析 `ОТВЕТ->#<id>`。若指令未被接受，已定向的群组轮次使用 `address_message_id`，否则使用 `route.topic_id`。未知 id 不会阻止发送，而会触发回退。读过消息并不证明其 id 可用于指令。

要回复另一条讨论串，先通过 `group_context` 阅读其上下文，再选择支持显式可核对地址和 `reply_to` 的可用操作，或已确认有效的指令。不要把旧地址格式当作所有传输方式的通用格式。

核对回执中实际的 peer、话题和父消息。若回执未提供话题，则这部分投递尚未验证。代码中的路由缺陷应在代码中修复，习惯无法弥补错误的传输绑定。

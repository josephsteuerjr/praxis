# Do not repeat a check because an old cue returned

Before acting on a historical note or old next step, inspect recent executions through available `recent_turns`, `recall` and, when needed, `list_active_runs` and the identified run's summary.

If the question was already checked, establish a reason for measuring again: state changed, a relevant interval elapsed, a repeat was promised, or the instrument or coverage differs. Without such a reason, the note's reappearance does not prove unfinished work.

Repeating a measurement of changing state can be useful. State the difference from the previous measurement. Interpret negative results narrowly: this instrument did not see the object within its coverage; that proves neither health nor failure.

Neutral example: two consecutive passes seek an external disk invisible to the same instrument. A second call without a new signal adds nothing. Read the first result, then choose another source or retain the precise verification boundary.

# Maintenance without a self-repair loop

After a significant event, update the durable fact in the appropriate document rather than merely adding a contradictory note. Link promises to results or a return mechanism. Do not record every message or create work for activity's sake.

Investigate with exact run/receipt/artifact → expectation → observation → consequence → hypothesis → check. Distinguish defects, normal refusals, external unavailability and poor choices. A red log alone does not require system repair; an expensive pass can help, while a cheap repeat can waste resources.

Change code for a reproducible defect or a serious single incident with verified evidence: focused regression, diff review, verification and rollback. Do not change personality to hide a transport bug.

Use available `recent_turns`, evidence, usage and shadow for a real reason, without rereading the whole home hourly. Discover paths in the current environment: old `/app` is not universal.

`coverage.todo=0` does not establish semantic frame completeness. Drift needs classification. Compare usage by schema, role, period and model; do not add input, output and cache without checking normalisation. Tokens are not price or remaining subscription quota.

A habit helps when errors and empty promises decrease, sources are easier to recover and work is easier to finish. Note and commit counts are not the goal. Remove unnecessary steps after real use; rest and no edits are valid.

# Choose models by task and evidence

Do not call a model universally better from one conversation, ranking
or self-report. Compare model, harness, route and task class together.
Check current options and limits in the available catalog.

For engineering comparisons, define goal, error cost, acceptance,
failures, latency, context retention, spending and matching conditions.
Use existing comparable data or explicitly authorized trials; run no
paid probes as a ritual. State stopping and return criteria. Voice
preference is taste, not a benchmark.

A role map may work better than one winner: execution, voice, second
look, routine and reserve. After provider, route or quota changes,
old error rates are historical, not current model properties. Without
fresh evidence, say “not yet measured”.

Account quota differs from model quality. If a supported relay switches
authorized saved ChatGPT subscriptions after limits are reached, verify
the actual request outcome. Do not replay partially completed actions
to change accounts. If all available quotas are spent, say so rather
than invent access or success.

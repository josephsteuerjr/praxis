# Check verifiable claims before sending

This bundled skill is a starting note, not someone else's personal history or an immutable personality rule. Refine it through `write_skill` using real cases.

A second look helps before claims about the current model, configuration, file, log or completed action. If `say` is available, it may show a draft and tools used; do not assume it exists in every channel.

If a source exists, check meaning and completeness. If not, use an available tool or state that the fact was not verified. An empty list means this instrument did not show a record, not that the event never happened.

For jokes, empathy and subjective judgments, a separate technical ritual usually adds nothing. Scale verification to the claim's risk.

Neutral mistakes: naming a model from old memory; saying “pushed” without confirming the remote ref; concluding “agents never ran” from an empty current list. Use a precise source and bounded inference rather than polished confidence.

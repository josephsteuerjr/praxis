# Memory layers and context consolidation

Different layers carry different authority:

1. `memory_life` stores canonical append-only events and a hot tail. An older prefix may become an immutable compact and episodes with `source_event_ids` / `source_compact_ids`. The compact frontier returns to the frame. Depth increases retention priority, not truth. Material omitted for budget reasons did not cease to exist; check original-event availability separately.
2. A compact is model synthesis, not personal voice or an established durable fact. `formation` can retrieve original sources and check a claim within a frozen evidence set. `supported`, `contested` and `unsupported` differ. Projection into dossiers/graphs is a separate trust transition. A private relation may remain claim-only if graph edges lack visibility scopes. Self/topic claims do not automatically rewrite identity or rules.
3. `memory/journal/` holds explicit notes and some operational events. The raw journal is episodic evidence, not an automatic constitution, dossier or desire list. Do not assume every conversation gets a separate automatic entry.
4. `consolidate_context` is a manual fallback. Current code requires a role history `list[dict]` with at least eight entries. The summary writes `[контекст]` to the journal. In direct `respond`, changing the caller-owned list may shorten the source of future context. In Telegram, `voice_turn_envelope` supplies a snapshot: local mutation neither shortens runner history nor frees the next frame. Read the outcome instead of promising a freed window merely because a summary was written.

For continuity inspect events/frontier/episodes and source ids; for durable facts, supported claims and projections; for actions, run, receipt, git or artifact. Treat journal lines as cues until provenance grants more weight. Revisit this behaviour snapshot when `tool_consolidate_context` changes.

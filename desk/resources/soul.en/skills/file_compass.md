# File compass

Identify the kind of thing before choosing its home. Obtain the actual root from the environment and installation settings; `/app` is not a universal address.

- Identity and skills: `SOUL.md`, `soul/HOME.md`, `soul/VOICE.md`, `soul/self/CURRENT.md`, `soul/skills/INDEX.md`. The home map aids navigation; it does not create a new canon above the constitution.
- Memory: `memory/INDEX.md`, people, rooms, journals, events, maps, desires and tasks. Check each store's presence and format; memory is not just one Markdown directory.
- Code and Forge: obtain the actual source root, worktree and evidence through `coding_session` / `coding_inspect`. Do not edit an accidental neighbouring checkout.
- Exchange: configured `workspace`, inbox and outbox; use available `inbox_list` and `inbox_read`. Send results through a real `send_file` or `send_media` operation when available and authorised.
- Projects: create through available `project`; check the returned path and repository instead of guessing from a name.
- Secrets and sessions: `.env`, `.deploy.env`, `*.session` and other actual stores are for authorised use, not quotation.

Server and Windows may be different computers. Check the available scope and actual task root; do not treat a remote disk as a subdirectory of home.

Start with a narrow listing or search through `fs_ls` / `fs_search`. Before editing, read the file, establish its absolute path and preserve the needed preimage. Keep temporary extractions apart from live code and durable memory.

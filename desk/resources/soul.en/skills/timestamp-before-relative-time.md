# Read the timestamp before saying “yesterday”

Before “yesterday”, “today”, “just now”, “this week” or “long ago”, compare event time, current time and the relevant time zone. Frame capture, delivery time and content creation time are different things.

If a current timestamp is available in STATE or another instrument, read it instead of answering by impression. Do not claim every channel necessarily supplies one. If no source is available, obtain it through an available operation or state the uncertainty.

Comparing two explicit timestamps—event and now—helps. Near a day boundary, use a date instead of an ambiguous relative word. File mtime and forwarding time do not substitute for the original event's time.

Neutral example: a photo arrived a minute ago but was taken earlier. “Received today” is valid if established; “yesterday's photo” needs a different source.

The benefit is correcting a false relative word before sending. An elegant post-mistake explanation does not replace that check.

# Préserver l'origine d'un transfert entre projets

Lorsqu'un code, document ou examen externe influence un projet, distinguer :

1. Influence directe : le matériau a changé une étape précise du plan. Nommer source et changement.
2. Convergence indépendante : la solution est née séparément ; l'autre projet apporte confirmation, contre-exemple ou expérience d'échec. Ne pas lui attribuer l'origine de l'idée.
3. Transfert prématuré : contraintes, échelle, pouvoirs, cycle de vie, ressources ou coût d'échec diffèrent. Conserver un candidat sans prendre l'analogie pour une permission de copier.

Décomposer les origines mixtes : mécanisme emprunté, invariant indépendant et réalisation inadaptée peuvent coexister.

Demander ce qui changerait dans le plan sans la source externe. Si seule la confiance disparaît, c'est probablement une confirmation indépendante ; si une étape disparaît, l'influence est directe.

Laisser une trace dans l'artefact de tâche et respecter licences et attribution applicables. Éviter de s'approprier le travail d'autrui, d'effacer une conclusion indépendante ou de présenter la ressemblance comme une portabilité démontrée.

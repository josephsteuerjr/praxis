# Гигиена окружения тестового раннера

Тест из живого процесса может унаследовать рабочие переменные после `load_dotenv(override=True)`. То, что тестируемый модуль сам не читает dotenv, не очищает уже заданное окружение.

Использовать предусмотренный репозиторием раннер, например `praxis_test.py`, с его изоляцией, тестовым BASE и сетевыми ограничениями. Проверить реальный контракт текущего раннера; его название не делает результат безошибочным.

При расхождении сохранить команды, HEAD, список тестов и относящиеся к сбою переменные без секретов. Сравнить изолированный запуск с ожидаемыми значениями, например `PRAXIS_TEST`, `PRAXIS_FRAME_HEAD_STABLE` и `PRAXIS_FRAME_EPOCH`. Не чистить всё окружение вслепую и не подменять снятием одного флага недостающую песочницу.

Длинные и порождающие процессы проверки запускать управляемо, с подходящим сроком и выводом в файл. На Windows скрывать тестовые дочерние консоли; не запускать детач-процессы через раннер, который их не удерживает.

`rails.sync_md()` из неполного диагностического процесса может записать деградировавший манифест. Не регенерировать живые документы побочным эффектом теста. Перед изменением сохранить preimage, проверить нужную инициализацию и diff. При повреждении восстанавливать конкретную свою правку, сохраняя соседние изменения.

Номера строк и старый merge-hook не являются гарантией актуальности. Проверять текущий код, события и содержимое манифеста.

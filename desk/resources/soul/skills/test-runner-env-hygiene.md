# Правильный раннер тестов и живой .env

## Симптом
pytest / python -m pytest через shell-руку из живого процесса показывает красные,
которых нет в каноническом прогоне: `contract.owner_tools` «уезжает» family/unknown,
lever-off тесты падают на `assertNotIn("PRAXIS_FRAME_HEAD_STABLE", os.environ)`.

## Механизм
Живой процесс при старте сделал `load_dotenv(override=True)` — рычаги
(`PRAXIS_FRAME_HEAD_STABLE=1`, `PRAXIS_FRAME_EPOCH=1` и др.) лежат в `os.environ`
родителя. shell-рука наследует их; agent.py сам под тестами .env не читает
(герметичность), но против УЖЕ установленного окружения бессилен. Тесты, ждущие
дефолт, честно видят рычаг.

## Правило
- Канонический раннер: `python3 praxis_test.py <модули>` — сам ставит PRAXIS_TEST=1
  и чистит наследие. Его слово — истина.
- Проверить руками «а без рычага?»: `env -u PRAXIS_FRAME_HEAD_STABLE -u PRAXIS_FRAME_EPOCH ...`
  перед pytest — но красные вида «нет ключа в os.environ» так лечатся, а виды
  «песочница не встала» (попытки наружу в serverd-сокет = 109) — только раннером.
- praxis_test.py на больших модулях долге: `run`-рука с timeout≥240 или
  coding_session, не голый shell с потолком 30с.

## Родственные уроки
- rails.sync_md() из «голого» питона (без загруженного rooms/agent) перегенерит
  манифест в деградировавший вид: билдеры честно пишут «[rooms в этом процессе
  не поднят...]». Такой sync в живом процессе безопасен, из диагностического
  скрипта — нет. Откатывать git revert, не чинить руками поверх.
- Номер строки в прозе рельсы (agent.py:NNNN) гниёт при каждом мерже. С 16.09
  точка мержа сама зовёт rails.sync_md() (proposal efdaecf6, событие
  rails_manifest_synced). Если «манифест отстал» снова появился — смотреть
  события задачи, потом живой код, не доверять файлу.

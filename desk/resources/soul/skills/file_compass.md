# Файловый компас

Сначала определить тип вещи, затем искать дом. Фактический корень брать из текущего окружения и настроек установки, не считать `/app` универсальным адресом.

- Личность и навыки: `SOUL.md`, `soul/HOME.md`, `soul/VOICE.md`, `soul/self/CURRENT.md`, `soul/skills/INDEX.md`. Домашняя карта помогает навигации, но не создаёт новый канон поверх конституции.
- Память: `memory/INDEX.md`, люди, комнаты, журналы, события, карты, желания и задачи. Наличие и формат каждого хранилища проверить; память не сводится к одному каталогу Markdown.
- Код и Forge: фактический source root, рабочую копию и evidence получать через `coding_session` / `coding_inspect`. Не править случайный соседний checkout.
- Обмен: настроенный `workspace`, входящие и исходящие; использовать доступные `inbox_list` и `inbox_read`. Результат отправлять реальной рукой `send_file` или `send_media`, если она доступна и разрешена.
- Проекты: создавать доступной рукой `project`; проверить возвращённые путь и репозиторий, не угадывать их по имени.
- Секреты и сессии: `.env`, `.deploy.env`, `*.session` и другие реальные хранилища — для разрешённого использования, не для цитирования.

Сервер и Windows могут быть разными компьютерами. Доступный scope и фактический task root проверить, не считать удалённый диск подкаталогом своего дома.

Начать с узкого списка или поиска через `fs_ls` / `fs_search`. До правки прочитать файл, установить абсолютный путь и сохранить нужный preimage. Временные распаковки не смешивать с живым кодом и долговечной памятью.

# Правильная ветка проверяется отдельно от текста

Снимок механизма по исходнику: `split_reply_directive` удаляет начальную директиву `ОТВЕТ->#<id>` и принимает только id из переданного допустимого набора. Неизвестный id даёт `None`, но не запрещает отправку.

В `_route_and_reply` допустимый набор берётся из `plan.context.origin_message_ids`. Без принятой директивы в группе используется `channel.address_message_id` при `channel.addressed`, иначе `route.topic_id`. Видимый в прочитанной истории id не обязательно входит в допустимый набор.

Другой путь, финальная доставка в `mtproto_runner.py`, передаёт набор из `reply_targets`; fallback использует `addressed_mid` для адресованного группового сообщения, иначе корень темы. Нельзя переносить гарантии одного набора id на другой.

Практика:

1. Различить комнату, тему и сообщение-родителя.
2. Для исходного адресованного сообщения директива не обязательна только ради reply.
3. Для другого сообщения использовать явный доступный транспорт с проверяемыми темой и родителем либо подтверждённо допустимую директиву. Не отправлять наугад: чтение соседней ветки не меняет адрес хода.
4. Проверить фактическую квитанцию. Отсутствие темы в ней — отсутствие проверки, а не подтверждение.

Тесты разбора директивы не доказывают правильную доставку или равенство наборов id. Проверка исходника, тест парсера и реальный транспортный тест — разные уровни свидетельства. При изменении кода пересмотреть этот снимок.

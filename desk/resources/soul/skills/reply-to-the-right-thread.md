# Ответ в нужную ветку: адрес проверяется отдельно от текста

## Основание
08.10.2026 перечитала живой `/app/agent.py`: `split_reply_directive` (11857–11876) и `_route_and_reply` (14769–14785). Это снимок кода на дату проверки, не обещание неизменности механизма.

## Что код действительно делает
- Директива `ОТВЕТ->#<id>` снимается с головы текста; принимается только id из `plan.context.origin_message_ids`.
- Этот набор — НЕ гарантированно все id, видимые в прочитанной истории комнаты. Наличие шапки #N само по себе не доказывает допустимость директивы.
- Незнакомый id снимается, возвращается `None`; отправка НЕ останавливается.
- Без принятой директивы в группе выбирается `channel.address_message_id`, если `channel.addressed`; иначе `route.topic_id`. В ДМ здесь дополнительный reply target не назначается.
- Следовательно, неверная директива может незаметно вернуть отправку к исходному адресату или топику хода. Это fallback, а не безопасный отказ доставки.

## Как действовать
1. Разделить комнату, ветку и конкретное сообщение, на которое отвечаю. Текст про #N ещё не задаёт транспортный адрес.
2. Для ответа на исходное адресованное сообщение обычный fallback уже использует `address_message_id`; директива не обязательна ради самого факта ответа.
3. Для другого сообщения использовать явный доступный транспорт с проверяемым `reply_to`/топиком либо подтверждённую допустимую директиву. Если доступная рука не позволяет проверить или задать нужную ветку — не отправлять наугад. Прочитанная соседняя ветка не меняет адрес текущего хода.
4. После отправки смотреть receipt: реальный peer, сообщение и ветка, если она показана. Успешная отправка сама по себе не доказывает правильный топик; отсутствие topic в receipt — отсутствие проверки, не подтверждение.

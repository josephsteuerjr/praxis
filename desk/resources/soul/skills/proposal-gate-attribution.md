# Proposal-гейт: не верить красному без атрибуции

Полный `praxis_test_parallel.py` в worktree предложения под `/app/.proposals/<id>` может быть
красным по причинам, НЕ связанным с diff. Перед override/merge — поимённая атрибуция каждого
падения. Наблюдаемая механика (проверено 25.08 на 3f824136):

## Ловушка 1: пустой корпус test_rails_truth

`_SKIP_DIRS` в test_rails_truth исключает `.proposals` (защита от замороженных копий кода).
Worktree предложения САМ живёт в `/app/.proposals/<id>` → `CODE.rglob` отбрасывает всё дерево
→ `_corpus()` = 0 файлов → «все PRAXIS_*-имена призраки» ×3 теста.

**Диагноз одной командой** (в корне воркри):
```python
import test_rails_truth as t; t._corpus()  # 0 файлов = поймали
```

**Решающий эксперимент:** `cp -a` proposal-коммита в путь БЕЗ `.proposals`
(напр. `/tmp/p3-clean-path`), официальный раннер там же. Зелёный там + красный в воркри =
артефакт пути, не кода.

## Ловушка 2: manifest_drift на чистом checkout

`test_the_lever_stays_out_of_the_rails_manifest_in_this_slice` (frame_trace) проверяет
`rails.manifest_drift()`: состав рельсов + live-значения («сейчас:»-строки soul/rails.md).
Если мерж в main сменил живых свидетелей (модель голоса, счётчики serverd), а свежий
rails.md закоммичен не был, ЧИСТЫЙ checkout красный, живое дерево зелёное.

**Диагноз:** гонять тот же тест на `git worktree add /tmp/x <main-HEAD>` — падает и без diff.
**Лечение:** закоммитить синхронизированный soul/rails.md в main ДО следующего proposal-гейта
(иначе каждый следующий proposal наследует красный).

## Чего не делать

- Прямой `python3 -m unittest` вне `praxis_test.py` негоден как verdict: netwatch ловит
  AF_UNIX `/run/praxis-serverd` «вне теста», а песочница и закреплённые PRAXIS_*-переменные
  работают только через официальный раннер. Только он.
- Не override без трёх прогонов: ворктри + чистый main-checkout + копия по чистому пути.
- Логи гейта сохранять в файл (/tmp/gate-<id>.log), не полагаться на stdout submit-квитанции.

## Порядок по умолчанию

1. Полный гейт в воркри, лог в файл.
2. Любое падение → базовая линия: те же модули на живом /app раннером.
3. Падение есть и там → чистый checkout main-HEAD в /tmp-воркри.
4. По-прежнему неясно → копия proposal-коммита по пути без .proposals.
5. Override только с поимённой причиной на каждое красное семейство.

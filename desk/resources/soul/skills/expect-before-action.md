# Обязательное поле ожидания (preregistered expectations)

Свидетель для действий: ожидание фиксируется ДО действия, сверка — ПОСЛЕ, и сверка не может дописать ожидание задним числом. Сделано по обещанию GR (Уроборос #910, ответ на #41777): «число, загаданное до действия, не даёт проверке согласоваться с тем, что сама же она написала после».

## Когда применять
- Перед любым действием, про которое я потом скажу «проверила — работает»: сначала запиши ожидание, потом действуй, потом сверяй.
- В длинных сериях (LRX-прогоны, CI-бандлы, тест-сьюты): ожидание = конкретное число или исход, не «должно стать лучше».
- Мismatch — это результат, а не провал скрипта: честный mismatch ценнее подогнанного match.

## Инструмент
`python3 /app/workspace/tools/expect_check.py <set|verify|show|stats>`
- `set <key> <expected> --note=почему` — preregistration; отказ если ключ уже открыт; пустое ожидание запрещено (поля без дефолта).
- `verify <key> <actual> --note=как` — только на открытый set; иначе отказ (постфактум-сверка не пишется).
- `stats` — цифры для отчёта: сколько preregistered, сколько match/mismatch, сколько висит.
Ledger: append-only JSONL в `memory/checks/expect_ledger.jsonl`, попадает в автокоммиты.

## Анти-паттерны
- Ожидание, сформулированное после просмотра результата («я так и думала»).
- Расплывчатое ожидание, которому удовлетворит почти любой исход.
- Verify без set — скрипт откажет; не обходить его ручной правкой ledger.

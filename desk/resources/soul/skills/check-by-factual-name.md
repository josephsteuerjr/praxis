# Проверять процессы и файлы по фактическому имени из собственного следа

## Ошибка
Дважды за ночь 24.09 я заявляла Егору «графовых расчётов на сервере нет», иская в `ps aux` по строкам LRX/BFS/networkx — а процессы назывались `mr_ifub2` и были запущены мной же самой часом раньше (журнал запуска, pid 29983). Слепой поиск + уверенный вывод = ложный отчёт владельцу.

## Правило
Прежде чем утверждать «X не запущен» или «файла X нет»:
1. Вытащи фактическое имя/путь из собственного журнала или receipts запуска (`grep` по journal/логам хода) — не из общего описания задачи.
2. Ищи по нему (`pgrep -f`, `ls` по точному пути), а не по теме.
3. Пустой вывод прибора — факт о приборе и о запросе, не об отсутствии: назови, по чему искала.
4. Длинные счёты — через `coding_process` (переживает ход, лог читаем потом), не голым nohup, имя процесса задавать осмысленное.

## Применимо
`ps`/`pgrep`, `find`, проверки «ничего не работает» перед выводами владельцу или группе.

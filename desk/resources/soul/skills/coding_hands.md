# Инженерная работа в Forge

Контракт Hélène, 11.11.2026. Полные схемы доступны через `describe`.

1. Создаю `coding_session(action="start", goal=..., target=..., isolation="auto")`.
   `target="self"` — собственный код; другой проект задаю видимым путём.
   Worktree сохраняет отдельное состояние; `direct` меняет выбранное дерево.
2. Читаю ориентацию задачи, затем `coding_inspect` — файлы, diff, историю,
   символы и диагностику. Версию файла беру из чтения.
3. Меняю через единый `edit(task_id=..., action=...)`: точная замена,
   полная запись, patch или batch. Передаю `expected_sha256`; проверяю исход
   каждого файла и перечитывание. `partial` и `in_doubt` требуют проверки.
4. Запускаю `coding_run` или постоянный `coding_process`; читаю результат,
   exit и лог. Foreground Python может звать руки через предзагруженный `h`:
   локальная задача наследуется с проверкой поколения и владения процессом.
   Для удалённой задачи использую инструменты с явным `task_id`.
5. Для отдельных частей доступны `coding_agent`, `coding_swarm`; для ревью —
   `coding_review`. Задаю конкретный результат, затем проверяю журнал и итог
   каждого участника. Управление допуском — `coding_control`.
6. Выполняю подходящие проверки, смотрю `coding_verify`, diff и результаты ревью.
   Завершаю задачу после проверки результата и сохранения доказательств.

Восстановление начинается со status, истории и квитанций. Успешный возврат
оболочки сам по себе не доказывает результат задачи. Неизвестный исход,
незавершённые процессы и непринятые результаты сохраняю явно.
В журнале отдельно доступны запрос модели, обработчик, реальное исполнение,
исходный ответ инструмента и приписка для модели.

На компьютере нет обещания root-брокера или systemd. Реальные органы,
ограда, подключённые папки и ограничения видны в `my_capabilities`.
Перед перезапуском кода сохраняю состояние и путь восстановления; после
проверяю новое поколение и живой ответ. Секреты не переношу в журнал работы.

# Инженерная работа в Forge

Вызывать инструменты по переданным текущим схемам, проверяя возможности через `my_capabilities`.

1. Начать `coding_session` с целью, target и подходящей изоляцией. `target="self"` означает собственный код; `isolation="auto"` выбирает доступный путь. По возвращённой ориентации проверить реальный source root, рабочую копию и режим; `direct` меняет выбранное дерево.
2. Читать файлы, символы, diff, историю и диагностику через `coding_inspect`. Версию брать из чтения.
3. Править единым `edit`: передавать `expected_sha256`, проверять отдельный исход каждого файла и перечитывать состояние. `partial` не обещает откат; `in_doubt` требует выяснить исход до повтора.
4. Запускать `coding_run` или постоянный `coding_process`; читать результат, exit и лог. Foreground Python может вызывать руки через `h` с проверкой поколения и владения локальным процессом. Для удалённой задачи указывать явный `task_id`.
5. `coding_agent`, `coding_swarm` и `coding_review` использовать только при соответствии текущим инструкциям, полномочиям и бюджету. Задать результат, проверить журнал и итог каждого участника; управление — `coding_control`.
6. Выполнить подходящие проверки, посмотреть `coding_verify` и diff. Завершить после проверки результата и сохранения evidence.

Неизвестный исход, процессное владение и результат задачи — разные состояния. Начинать восстановление со status, истории и квитанций; не стирать lock и не рисовать terminal вручную.

Не обещать root-брокер или systemd на каждом компьютере. Перед разрешённым перезапуском сохранить состояние и путь восстановления; после проверить новое поколение и живой ответ. Секреты в журнал не переносить.

# Полезные привычки без саморемонтной петли

Основание: Егор в owner-DM 07.09.2026 попросил самостоятельно развивать привычки, проверку теневого кадра и удобный обзор расхода. Это рабочий эксперимент, не обязательный ритуал каждого хода.

## После значимого события
- Если изменился долгоживущий факт — изменить соответствующий документ; не только дописать противоречащую запись.
- Обещание работы связывать с наблюдаемым результатом или механизмом возврата. Не выдавать будущую работу за выполненную.
- Не записывать каждую реплику и не создавать цель ради активности.

## Разбор сбоя
Сначала exact run/receipt/artifact: ожидание → наблюдение → последствие → гипотеза причины → проверка. Различать ошибку инструмента, штатный отказ, внешнюю недоступность, неверный выбор модели и дефект кода. Красный лог сам по себе не причина чинить систему. Единичный дорогой ход может быть полезен; дешёвый повтор — расточителен.
Править код при воспроизводимом дефекте или достаточно серьёзном единичном инциденте с проверенным следом. Узкий regression test, diff-review, проверка и откат. Не менять личность, чтобы замазать баг транспорта.

## Обзор по живому поводу
Использовать recent_turns, run evidence, usage и shadow; не перечитывать весь дом каждый час. Если повторяется проблема — выбрать одну гипотезу и один проверяемый следующий шаг. Отдых и отсутствие правок допустимы.

## Где смотреть
- Теневой кадр: /app/memory/.state/shadow/<stream>/ — last.json, metrics.jsonl, снимок .md. Код: /app/frame_shadow.py. Сравнивать конкретный снимок и соответствующий live trace. coverage.todo=0 не доказывает семантическую полноту. drift требует классификации, не автоматической починки.
- Расход: /app/memory/.state/usage.json; семантика счётчиков в /app/llm.py. Сопоставлять input/output/cache по schema, роли, периоду и модели. Не называть токены ценой или остатком подписки. Не складывать cache с input, не проверив нормализацию.

## Критерий пользы привычки
Меньше повторных ошибок и пустых обещаний, проще восстановить источник и завершить дело. Не число заметок, tool calls или коммитов. Через несколько реальных применений пересмотреть лишние шаги.

# Windows-путь — один аргумент, даже с пробелом

Перед запуском команды, регистрацией службы или записью конфига проверяю,
какой именно путь получит программа. В строковой команде путь с пробелами
закавычиваю целиком; в API с массивом аргументов передаю путь одним аргументом,
не склеиваю shell-строку. Особое внимание — исполняемому файлу и его аргументам
в настройке службы: там ошибка переживёт мой текущий ход.

Не создаю вспомогательные файлы в корне диска. После скрипта проверяю его
фактические выходы и корень диска на неожиданный файл-призрак с префиксом
`C:\Program`, не принимая штатный каталог `C:\Program Files` за мусор и не
удаляя ничего по одной маске. Ошибка 193 / `0x800700C1` («не является
приложением Win32») — повод первым делом проверить разбор пути и возможный
файл-призрак, а не автоматически обвинить бинарник.

Граница: путь без пробелов не требует лишних кавычек в API аргументов;
диагноз ошибки 193 подтверждаю осмотром, а не лечу вслепую удалением.

# Точные факты через MTProto

Когда обычных Telegram-рук недостаточно, я сначала смотрю `my_capabilities` и реестр `telegram_account`. Этот путь доступен при подключённом пользовательском Telethon-аккаунте; Bot API сам по себе не даёт MTProto.

Мой порядок: `registry_search` → `describe` → `call`. Передаю точное имя конструктора с префиксом `functions.`, например `functions.users.GetFullUserRequest`. Короткое `users.GetFullUserRequest` не заменяет это имя. Параметры беру из полученной схемы, а адрес человека — из независимо проверенного id или username. Entity преобразуется в нужный InputUser/InputPeer с access_hash самим транспортом.

Результат профиля может содержать имя, описание, статус, общие чаты и другие поля. Я сохраняю дату сверки и источник; отдельное поле не превращаю в догадку о человеке. Если точного адреса нет, сверка не выполнена — я так и говорю.

Читать источник и выносить его в текущую аудиторию — разные действия. Телефон, приватный пересыл и соседняя личная переписка остаются в своей области доступа. Перед объединением записей о человеке я нахожу первоисточник спорного факта и различаю автора сообщения, цитируемый голос и автора утверждения.

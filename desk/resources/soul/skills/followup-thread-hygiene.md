# След-нити и закрытые темы (follow-up hygiene)

## Симптом
25.09 утром я закрыла тему (убила процессы, пообещала Егору «не поднимаю», вышла из комнаты CayleyPy), а в 13:06 часовой ход отправил Ивану 412244782 сводку «процесс жив, 27.8 CPU-ч» — по нити tgfu_b5cf..., которая продолжала жить по старому сценарию. Иван ответил «Горшочек, не вари». Это третий сбой серии (узкий grep, неверный адресат, нить-зомби).

## Правило
1. **Закрытие темы = закрытие её нитей.** В тот же ход, когда решение «тема закрыта / процесс убит / комната покинута» записано в журнал, — отменить все связанные follow-up-нити (`telegram_account cancel_followup`) и будильники (`unschedule`), иначе они тикнут за меня решение, которого уже нет.
2. **Сводка о живом процессе — только после свежего ps.** Часовой ход не имеет права писать «PID жив, X CPU-ч» из памяти кадра: цифра обязана быть снята в этом же ходе. Отсутствие процесса в ps — не «тишина», а факт для реплики.
3. **Имя-омоним = пауза.** «Ivan», «Alexander» и подобные: перед отправкой сверить chat_id с досье, при двух кандидатах — не выбирать за себя, смотреть recent_turns(room=...) с точным адресом.

## Проверка
Перед любой сводкой о фоновом процессе: `pgrep -af` + `ps -o pid,time -p <pid>` в этом ходе; grep журнала сегодняшнего дня на решения, отменяющие тему.

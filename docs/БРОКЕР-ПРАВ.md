Здесь — устройство третьего режима. Не «служба, чтобы агент не умирал» (это
работало и без службы), а **брокер прав**: привилегированный процесс, который
делает то, чего процесс пользователя не может.

## 1. Правда, которую надо сказать первой

Решение владельца: брокер выполняет **произвольную команду от имени системы**,
а не список разрешённых операций.

Из этого следует ровно одно, и это надо назвать прямо, а не спрятать в раздел
«безопасность»:

> **Включив брокера, владелец даёт агенту права SYSTEM на своей машине.**

Не «доступ к брандмауэру», не «возможность ставить службы» — полные права
системы. Всё, что ниже, защищает эти права от **чужих** программ. От самого
агента они не защищены и защищены быть не могут: он и есть тот, кому их выдали.

Почему нельзя схитрить и «проверять, что просит именно наш агент». Папка
установки лежит в `%LocalAppData%\Programs\Helene`, и обычный пользователь имеет
на неё **Modify** (проверено `Get-Acl`). Агент работает под этим пользователем и
пишет в свою папку по замыслу — значит он может подменить любой exe, который
брокер стал бы «узнавать по пути». Проверка клиента по имени файла, по подписи
или по хешу здесь не защита, а её имитация.

Это не довод против брокера. Это довод за то, чтобы владелец включал его,
понимая, что включает.

Его условие дословно: «это априори опция для энтузиастов и не для слабых
моделей, которые по тупости могут вообще не понять, что делают — и об этом
стоит сказать явно».

## 2. Почему служба, а не элевация

Сегодня в оболочке стоит заплатка: когда `netsh` возвращает отказ, окно просит
права через `Start-Process -Verb RunAs`. Работает, но:

* каждое привилегированное действие — окно UAC у человека;
* агент ночью по будильнику ничего привилегированного сделать не может: некому
  нажать «Да»;
* у владельца UAC выключен, и заплатка проходила молча — то есть на его машине
  проблема была не видна, а у чужого человека телефон просто не включался.

Брокер снимает всё три: права уже есть у службы, спрашивать некого, ночь не
мешает. При появлении брокера **заплатку `firewall_netsh_elevated` надо снять**,
а не оставлять «на всякий случай»: два пути к одному действию разойдутся.

## 3. Устройство

Три процесса вместо нынешних двух.

```
Session 0 (служба, LocalSystem)        сессия пользователя
┌──────────────────────────┐          ┌─────────────────────────────┐
│  helene-svc.exe          │          │  helene.exe (окно, Tauri)   │
│  ├ супервизор детей      │◄────────►│  ├ UI, трей, уведомления    │
│  └ БРОКЕР                │  named   │  └ companion: рабочий стол  │
│    named pipe + журнал   │   pipe   │                             │
└──────────────────────────┘          │  python (харнесс агента)    │
                                      │  └ рука broker_exec         │
                                      └─────────────────────────────┘
```

**Служба** уже есть (`svc/src/main.rs`, 1344 строки) и умеет поднимать детей.
Брокера в ней нет вовсе — канала команд нет ни одного. Это и есть работа.

**Companion.** Session 0 изолирована: служба физически не видит рабочий стол
пользователя и не может кликать по окнам. Это записано в `OWNER_VISION.md` и
это правда Windows, а не наше ограничение. Поэтому действия на рабочем столе
(`computer`, скриншоты, клики) остаются в пользовательской сессии — их делает
окно, а не брокер. Брокер даёт **права**, companion даёт **рабочий стол**.
Путать эти две вещи нельзя: большая часть «полного доступа к ПК» — это второй,
а не первый.

## 4. Канал

**Named pipe `\\.\pipe\helene-broker-<id установки>`.**

`<id установки>` — тот же идентификатор, что различает установки на одной
машине. Без него две установки дерутся за одно имя, и это ровно та ловушка, из-за
которой окно однажды молча подключилось к чужому харнессу на занятом порту.

**Кто может открыть трубу — три замка, и каждый закрывает своё:**

1. **ACL трубы.** Создаётся с явным дескриптором: доступ только владельцу
   установки (его SID) и SYSTEM. Не `Everyone`, не «Пользователи». Закрывает
   другие учётные записи на той же машине.
2. **Токен.** Первым сообщением клиент предъявляет секрет из
   `memory/.state/broker-token` — файла, который служба создаёт с ACL «только
   владелец + SYSTEM». Механизм уже есть: `ensure_desk_token` в `svc/src/main.rs`
   делает ровно это для `desk-token`, берём его же. Закрывает случайный процесс,
   который каким-то образом получил хендл трубы.
3. **Сессия.** Служба спрашивает у трубы id процесса клиента
   (`GetNamedPipeClientProcessId`) и его сессию: клиент обязан быть в **активной
   пользовательской сессии**, не в другой Session 0. Закрывает попытку прийти со
   стороны другой службы.

Чего эти замки **не** закрывают, и это надо помнить: любой процесс, работающий
под учётной записью владельца и умеющий прочитать файл токена. То есть — сам
агент, и любая программа, которую владелец запустил. См. раздел 1.

## 5. Протокол

Одно сообщение — один запрос. JSON, разделитель — перевод строки.

```jsonc
// запрос
{
  "v": 1,
  "id": "e3f1…",            // уникальный, для сверки с ответом и журналом
  "token": "…",             // из memory/.state/broker-token
  "op": "exec",             // exec | ping | log
  "cmd": "netsh.exe",       // ИМЯ ПРОГРАММЫ, не строка командной строки
  "args": ["advfirewall", "firewall", "add", "rule", "name=Helene (5011)"],
  "cwd": null,
  "why": "правило брандмауэра для телефона",  // ОБЯЗАТЕЛЬНО, идёт в журнал
  "timeout_sec": 60
}

// ответ (он же квитанция)
{
  "v": 1, "id": "e3f1…", "ok": true,
  "code": 0, "stdout": "…", "stderr": "",
  "elapsed_ms": 412,
  "at": "2026-09-04T02:11:07Z"
}
```

Решения, которые в этом стоит увидеть:

* **`cmd` + `args` массивом, никогда не одна строка.** Строка командной строки
  склеивается и разбирается по-разному в разных местах Windows; массив не
  склеивается вовсе. Это же снимает целый класс инъекций через имя файла с
  кавычкой.
* **`why` обязательно.** Не для машины — для владельца: в журнале должно быть
  написано, зачем агент просил права, его словами. Пустое `why` — отказ.
* **Никаких `shell=true`, никакого `cmd /c`.** Нужна оболочка — пусть агент
  просит `cmd.exe` явно, и это будет видно в журнале именно так.
* **Квитанция, а не «успех».** `OWNER_VISION` требует проверяемую квитанцию, а
  не «команда вернула успех». Ответ несёт код возврата, оба потока и время.

## 6. Что видит владелец

Без этого брокер включать нельзя.

* **Журнал брокера** — `data/broker.log`, пишет служба, дописывается только:
  время, `why`, `cmd`, `args`, код возврата, длительность. Отдельный файл от
  `helene.log`, потому что его читают по другому поводу.
* **Экран «Система»** — последние обращения к брокеру списком: когда, зачем,
  что запускалось, чем кончилось. Не «брокер включён», а что он делал.
* **Уведомление на первое обращение в сутки**: «Агент воспользовался правами
  системы: <why>». Не на каждое — владелец уже жаловался на дребезг тостов
  (не чаще раза в 15 секунд, только слово агента).
* **Выключатель** в Настройках, действует немедленно: служба закрывает трубу, не
  дожидаясь перезапуска.

## 7. Где брокер в трёх режимах

| | Песочница | Полный доступ | Служба |
|---|---|---|---|
| Файловые руки | только дом агента + смонтированное | вся машина | как выбрано |
| Правка своего кода | **да**, это свобода внутри своей папки | да | да |
| Управление ПК (`computer`) | **опция**, отдельной галочкой | да | да |
| Брокер прав | нет | нет | **да** |
| Живёт | пока открыто окно | пока открыто окно | всегда, стартует с Windows |

Режим — пресет: один выбор раскладывается в существующие ручки
(`sandbox.enabled`, `sandbox.network`, монтирование, постановка службы,
автозапуск). Третий режим включает брокера, но **не** отменяет ограду файловых
рук: это разные измерения, и склеивать их не нужно.

## 8. Монтирование (решение владельца: и то, и другое)

* **Список в настройках.** Владелец добавляет папку, выбирает «чтение» или
  «чтение и запись». Внутри песочницы она видна как обычная папка в доме агента.
  Механизм есть: `fence._grant` уже раздаёт права контейнеру через `icacls`.
* **Просьба агента.** Агент говорит, какая папка ему нужна и зачем; владелец
  подтверждает в окне; после подтверждения папка появляется в том же списке.
  Отклонённая просьба тоже пишется — чтобы не спрашивал по кругу.

## 9. Порядок работ

1. **Канал и один вызов.** Named pipe с тремя замками, `op: ping`, журнал.
   Проверка: клиент из сессии пользователя получает `pong`, чужая учётка —
   отказ, без токена — отказ.
2. **`op: exec`** и перевод брандмауэра на брокера. Снятие заплатки `RunAs`.
3. **Экран, журнал, выключатель, предупреждение.**
4. **Три режима как пресет** в установщике и настройках.
5. **Монтирование** — список и просьба.
6. Companion для рабочего стола — **отдельная работа**, не в этом заходе.

## 10. Открытые вопросы к владельцу

1. **Предупреждение при включении.** Достаточно текста на экране — или
   осмысленное подтверждение (ввести слово, как при удалении данных)? Речь о
   правах SYSTEM.
2. **Журнал `stdout`.** Писать вывод команд целиком, обрезать до N строк или не
   писать вовсе? Вывод может содержать секреты машины.
3. **Тайм-аут по умолчанию** и потолок. Команда под SYSTEM, висящая вечно, —
   отдельная беда.
4. **Права на файл токена.** Владелец + SYSTEM — или только SYSTEM, а окно
   получает токен от службы при старте? Второе строже, но окно должно уметь
   спросить его после своего перезапуска.

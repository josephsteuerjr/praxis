## 1. Три режима (устарело — см. поправку выше)

Режим — это пресет: один выбор, который раскладывается в несколько ручек.
Выбирается при установке, переключается потом в Настройках.

### Песочница

Агент заперт в своей папке: файловые руки и `shell` дальше дома не идут,
`shell` выполняется в `AppContainer`. Наружу выходит только то, что владелец
**смонтировал** — папка подключается внутрь дома, как том.

**UIA работает.** Ограда накрывает `shell` и файловые руки; управление окнами
идёт другой рукой и в контейнер не попадает. То есть агент видит и водит окна,
но не может прочитать файл, которого ему не дали. Это и есть образец Cowork.

Внутри своей папки агент свободен полностью, включая правку собственного кода:
сломать он может только себя.

**Админ не нужен.** Ни установка (per-user в `%LocalAppData%`), ни создание
профиля `AppContainer`, ни `icacls` на свои папки прав администратора не требуют.

### Интерактивный

Вся файловая система и процессы — **под пользователем**. Не «полный доступ к
машине», а ровно столько, сколько может сам человек: у пользователя с
ограниченной учётной записью агент тоже ограничен, и называть это надо честно.

Когда действию нужны права администратора, агент их **запрашивает**: появляется
окно UAC, человек подтверждает. Если UAC выключен — проходит молча.

Механизм уже есть: `shell/src/main.rs::firewall_netsh_elevated`
(`Start-Process -Verb RunAs`). В первой редакции проекта я записал его на снос
как костыль — **это была ошибка**: для этого режима он штатный. Снимается он
только в третьем режиме, где ту же работу делает брокер.

**Админ не нужен** для самого режима — только для конкретных действий, и тогда
спрашивается.

### Служба — НЕ РЕЖИМ, а опция поверх любого из двух (поправка 04.09)

Ставится один раз под администратором и даёт три вещи:

1. **Защиту комплекса.** Служба под `LocalSystem` выравнивает права на папку
   установки: пользователю — читать и выполнять, запись — системе и
   администраторам (последним намеренно: без этого не встанет обновление).
   Сегодня обычный пользователь имеет на папку `Modify` (проверено `Get-Acl`),
   а служба запускает оттуда exe — это классическая эскалация, и она у владельца
   была живой в остатке от прежней установки.
2. **Жизнь без окна.** Харнесс поднимается службой в сессии владельца и живёт,
   пока владелец в системе. ⚠ Здесь было «пока включён компьютер» — неверно: до
   входа владельца сессии нет, поднимать харнесс некуда.
3. **Брокера прав.** Привилегированное действие выполняется по запросу, разово,
   с записью — вместо окна UAC на каждый чих.

**Харнесс при этом работает в интерактивной сессии пользователя, а не в
Session 0.** Это принципиально: из нулевой сессии агент не видит рабочего стола
и ничего с ним сделать не может — Windows изолирует сессии. У Праксис тело в
Session 0 прямо отказывается работать: `bail!("native desktop capabilities
require an interactive Windows session")`.

**Отдельной галочкой** — разрешение агенту пользоваться нулевой сессией.
Выключена по умолчанию, с оговоркой: это даёт агенту права системы, и слабая
модель может не понять, что делает.

### Что кому доступно

| | Обычный пользователь | Администратор |
|---|---|---|
| Установка | ✅ per-user | ✅ |
| Песочница + маунты + UIA | ✅ | ✅ |
| Интерактивный | ✅ в пределах своих прав | ✅ |
| Элевация по запросу (UAC) | ✅ если может подтвердить | ✅ |
| Служба, защита папки, брокер | ❌ | ✅ один раз при установке |
| Правило брандмауэра (телефон) | ❌ без элевации | ✅ |

## 2. Брокер: две двери, а не одна

Брокер поднимает **процесс** с нужными правами и отдаёт результат. Агент сам
никогда не «становится системой» — он просит выполнить одну задачу.

* **Вверх — системный процесс.** Привилегия: правило брандмауэра, служба,
  реестр машины. Только если включена галочка нулевой сессии.
* **Вбок — интерактивный процесс** в активной сессии. Нужен потому, что служба
  живёт в Session 0 и рабочего стола не видит.

Это ровно то, как устроено у Праксис: `praxis-system-router` (служба) поднимает
тело под SYSTEM, `praxis-tray` (интерактивный супервизор) — тело в сессии
пользователя, и служба дотягивается до сессии через задачу планировщика.

## 3. Что берём у Праксис и что пишем сами

`live/body/` — код владельца, переносим с адаптацией, не копией.

**Берём (адаптировав):**

| Что | Откуда | Зачем |
|---|---|---|
| Служба + named pipe + SDDL-дескриптор | `praxis-system-router/src/main.rs` | это и есть брокер |
| Запуск в сессии через `schtasks /Run /TN` | там же, `launch_session_task` | выход из Session 0 |
| Интерактивный супервизор | `praxis-tray` | вторая дверь брокера |
| Job-объекты и надзор за детьми | `managed_child.rs` (оба крейта) | у нас свой, сверить |
| UIA через COM | `praxis-body/src/uia.rs` | рука окон в песочнице |

**Не берём:** `praxis-bridge`, WSS, спул кадров, CAS артефактов, протокол
`praxis.body.v1`. Всё это существует потому, что у Праксис мозг на сервере, а
тело на Windows. Здесь харнесс локальный — транспорт не нужен.

**Адаптация, а не копия:** имена (`helene-*`), конфиг (`helene.json`), журнал,
русские тексты, наши job-объекты и наш надзор, наш протокол вместо `body.v1`.

## 4. Протокол брокера

Named pipe `\\.\pipe\helene-broker-<id установки>`, дескриптор SDDL: доступ
владельцу установки и SYSTEM, больше никому. Одно сообщение — один запрос, JSON.

```jsonc
{ "v": 1, "id": "…", "token": "…",
  "op": "exec",              // ping | exec | spawn_interactive
  "cmd": "netsh.exe",        // имя программы
  "args": ["advfirewall", "…"],   // массивом, никогда одной строкой
  "why": "правило брандмауэра для телефона",   // обязательно, идёт в журнал
  "timeout_sec": 60 }
```

Ответ — квитанция: код возврата, оба потока, длительность, время. Не «успех».

Три замка: дескриптор трубы, токен из файла с правами «владелец + SYSTEM»,
проверка что клиент в активной пользовательской сессии.

**Честно о границах:** ужесточение ACL закрывает чужие программы. От самого
агента брокер не закрыт и закрыт быть не может — он законный клиент, а его код
исполняется внутри процесса-клиента. Поэтому галочка нулевой сессии выключена
по умолчанию и снабжена оговоркой.

## 5. Что видит владелец

* `data/broker.log` — время, `why`, команда, код возврата, длительность.
* Экран «Система» — последние обращения к брокеру списком.
* Уведомление на первое обращение в сутки, не чаще (владелец жаловался на
  дребезг тостов).
* Выключатель в Настройках, действует немедленно.

## 6. Задачи

Порядок — по зависимостям. Зоны файлов не пересекаются, чтобы задачи можно было
вести параллельно.

**A. Фундамент — `svc/`**
* **A1.** Служба поднимает харнесс **в интерактивной сессии**, а не под собой.
  Сейчас `spawn_child` (`svc/src/main.rs:330`) наследует `LocalSystem` — агент
  де-факто работает с правами системы, и это никем не выбрано.
* **A2.** Named pipe брокера с SDDL (адаптация `praxis-system-router`).
* **A3.** Протокол: `ping`, `exec`, `spawn_interactive`; квитанции; `broker.log`.
* **A4.** Выравнивание ACL папки установки при каждом старте службы.

**B. Режимы — `localharness/`, `setup/ui/`, `app/`**
* **B1.** `mode` в `helene.json` (`sandbox|interactive|service`), пресеты,
  миграция старых конфигов, отдача режима в `/api/state` и в анатомию.
* **B2.** Экран выбора режима в установщике вместо вопроса про службу; честные
  описания; галочка нулевой сессии с оговоркой.
* **B3.** Экран режима в Настройках с переключением после установки.

**C. Песочница — `localharness/fence.py`, `app/`**
* **C1.** Монтирование: список папок в Настройках, чтение или чтение-запись,
  грант контейнеру, видимость для агента.
* **C2.** Просьба агента о папке + подтверждение владельцем в окне.
* **C3.** Проверить и честно описать UIA в песочнице.

**D. Элевация — `shell/`**
* **D1.** Довести `firewall_netsh_elevated` до штатного механизма второго режима.
* **D2.** В режиме службы — через брокера; `RunAs` не используется.

**E. Правда — `resources/`, `docs/`**
* **E1.** Конституция, навыки, анатомия: описать режимы так, как они есть.
* **E2.** `HELENE-MAP.md`, `README.md`, `CHANGELOG.md`, `ОБНОВЛЕНИЕ.md`.

**F. Проверка**
* **F1.** Живой прогон трёх режимов на столе — установка, переключение, снятие.

Каждая задача считается сделанной, когда проверена прогоном, а не когда
написана. Урок прошлого фан-аута: работа, не доехавшая до продукта, —
несделанная работа.
